# Product Brief

> This file is the only starting point **a human writes first (a few lines)**. From here, `/req` firms up the requirements.

## What do you want to build? (1–3 lines)

4択問題集を、AI が分析・再構成して「耳だけでも効率的に学習できる形」へ変換する学習支援プロダクト。
問題文と選択肢をそのまま読み上げるのではなく、問題の背後にある知識・出題パターン・想起のキーとなる
単語の組み合わせ・紛らわしい選択肢どうしの違いを整理し、音声で「思い出して解ける」状態を作る。

## For whom / what problem to solve

4択形式の資格試験(AWS などの IT 資格を想定)を、問題集で対策している学習者。まずは作者自身。

- 机に向かえる時間が足りず、問題集を一周するのが精一杯で復習・定着まで届かない。
- 通勤・散歩・家事・運動といった「目と手がふさがっている時間」を学習に使えていない。
- 既存の読み上げ/音声フラッシュカードでは、選択肢が長い・専門用語が多い・類似選択肢がある・
  固有名詞が複数出る・A〜D を頭の中で比較する必要がある、といった 4択問題は聞くだけでは理解しづらい。

## Nice-to-haves (rough bullets)

- 類似問題の発見と、共通する知識の抽出(100問を、その背後にある少数の知識・出題パターンへ圧縮する)
- 出題パターンと正解の結びつきの学習(「この単語＋この状況＋この条件が出たら、この答え」という想起)
- 紛らわしい選択肢との違いの学習(「なぜ他の選択肢ではないのか」)
- 専門用語の説明、および試験に必要な最低限の概念理解
- 個人の弱点に応じた復習
- 音声での回答と、その AI 採点

## Non-goals (if any)

- 単なる読み上げ(TTS)。4択の原形をそのまま音声にすること自体は目的ではない。
- 視覚的な学習の完全な置き換え。机に向かう時間(実際に解く・詳しく理解する)は残す前提で、
  これまで学習に使えなかった時間を学習時間に変える補助的な位置づけ。
- 「音声を聞けた」ことをゴールにすること。

## Principles (non-negotiables) (if any)

- **評価軸は「解けるようになったか」**。学習後に元の問題または類似問題を正しく解けることを成否の基準にし、
  再生時間や消化量を成果とみなさない。
- **手段を固定しない**。一問一答・AI 講義・比較・想起など具体的な学習形式は学習効果を優先して選ぶ。
- **圧縮を重視する**。100問を100個の知識として扱わず、背後の共通パターンへ整理することを中心の仮説に置く。
- **パターン認識と概念理解の両立**。丸暗記に寄せると問題文が変わったときに崩れ、講義に寄せると試験対策として冗長になる。

## Constraints / assumptions (if any)

- 最初の教材は、作者が利用している Udemy の 4択問題集をそのまま使う想定。
- 他の問題集・PDF・テキストへ広げるか Udemy 専用にするかは未決定。
- 実装言語は **Python** を基本とする。UI が必要になった場合に限り **Next.js / React** の
  必要な方(または両方)を使う。

### 現時点で意図的に固定しないもの(プロトタイプで決める)

- 具体的な音声学習形式(一問一答 / AI 講義形式 / 4択をどの程度残すか)
- 音声で回答させるか、AI に音声回答を採点させるか
- 問題をどの単位でクラスタリングするか、「想起キー」の具体的な定義
- 復習アルゴリズム
- Udemy からの具体的な取り込み方法
- 提供形態(アプリ / Web / Chrome 拡張 など)
