# ADR-022: 想起素材の構造化スキーマ、G-1 照合先の定数化、問題ごとの再生成(ADR-010 の運用を改める)

- **Status**: proposed(「不合格の扱い」のうち含意判定の不合格は ADR-026 で改めた)
- **Date**: 2026-10-06
- **Decider**: human (finalized at the mandate)
- **Related requirements**: R-4、R-3、NFR-1

## Background / problem

前サイクルの実データの列で、想起素材の段が全件拒否された(ungrounded_keys 175/175、missing_options 47、DEF-1)。
3つの検査はすでに同じ述語 `grounding.presence.is_present` を呼んでいるが、生成プロンプトは照合先から逐語で抜き出すことを指示しておらず、照合先(本文全体)もプロンプトと別に定義されている。識別ポイントは本文中の括弧を選択肢への参照とみなして検査していた。

## Options

### 照合先とプロンプト
- **A(採用)**: 照合先を `grounding/targets.py` の定数(`RECALL_KEY_FIELDS = ("stem",)` など)にし、検査とプロンプトの両方をその定数から組み立てる。片方だけを変えるとテストが赤になる。
- B: プロンプトの文言だけを直す。照合先とプロンプトがまた別々に動きうる(前サイクルの原因そのもの)。

### 識別ポイントの参照
- **A(採用)**: 構造化した選択肢 ID の列(`distractor_ids`)で参照し、ID で検査する(D-177)。含意判定の reference に参照先の誤答の本文を加え、ID と本文の対応を守る(D-192)。
- B: 括弧の検査を直す。言い換えや引用符の揺れに弱い。

### 不合格の扱い
- **A(採用)**: 1問単位の検査とクラスタをまたぐ重複に落ちた問題だけを、上限 2 回まで再生成する(D-171、D-185、D-191)。含意判定の不合格と呼び出しの失敗は再生成しない。
- B: 含意判定の不合格も再生成する。判定器が通すまで引き直す形になり、NFR-1 の守りが弱まる。

## Decision
**Adopted**: 上の3つの A

**Reason**: 人の回答(D-170、D-171、D-176、D-177、D-191、D-192)。

細目(loop が決めた local の事項):
- スキーマ: `RecallDraft(key, answers: (AnswerElement(option_id, text), ...), discrimination: DiscriminationPoint(text, distractor_ids))`。識別ポイントは1問に1件で `distractor_ids` は1件以上(台本のセグメントの形を変えない)。
- 答えの要素は選択肢 ID を持ち、ID の集合が正解の集合と一致することを検査する。順序に意味を持たせない。
- 重複キーはクラスタをまたぐ場合だけ数え(D-200)、クラスタ順で後に来た問題を作り直す。
- 他クラスタ出現率とクラスタ要約の照合先は現行のまま本文全体(D-198)。
- 再生成の呼び出しは、既存の `begin_call`/`begin_invocation` が数えるので `llm_calls`・`provider_invocations` に自然に入る。
- 成果物の report に `regenerations`(問題ごとの回数)を足す。ログは件数だけ。
- 上限を超えた問題があっても全問を回し切り、超えた問題をすべて列挙して止まる(D-217)。
- 識別ポイントの reference は「正解」と「誤答選択肢(この問題では正しくない記述)」の節に分け、`ENTAILMENT_SYSTEM` に誤答節の意味を足す(誤答を正しい情報として渡すと、正しい識別ポイントが contradicted になるため)。台本段の識別ポイントも `distractor_ids` を引き継ぐ(台本段の判定は ADR-030 でやめた)。
- `reference_for(question, focus)` を `safety/entailment.py` に1本化し、3か所の重複した `_reference` を消す。答えの要素は focus にその要素の正解を明示し、正解 N 件も併記する。

## Consequences / results
- 想起キーの照合先が問題文だけになるので、検査は今より厳しくなる。汎用語キーの判定はプロンプトから他クラスタが見えないので、再生成は偶然に頼る形になる。上限超過で止まるリスクはフル処理まで残る。
- 呼び出し回数が増えるので、レート枠の使用率をリハーサルで測る(ADR-025)。

### What this requires of a person
- なし(コードの変更だけ)。想起キーが手がかりとして役立つかの主観の判断は前サイクルと同じ。

### Reversibility
- コミットを戻せば元に戻る。
