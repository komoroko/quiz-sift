# ADR-001: 製品の実行時依存をサンドボックスイメージに焼く

- **Status**: accepted
- **Date**: 2026-09-22
- **Decider**: human (finalized at the mandate)
- **Related requirements**: NFR-6, NFR-5

## Background / problem

品質ゲートは `network_profile: none` のサンドボックスで走る(NFR-6)。実測したところ、イメージには
`pytest / ruff / mypy / mkdocs / uv` しか入っておらず、製品の実行時依存は1つも無い。
`pyproject.toml` の `dependencies = []` だから現状ゲートが緑なのであって、LLM SDK・ブラウザ・
音声ライブラリ・形態素解析辞書を1つでも入れた瞬間に `pytest` が collection で落ちる。
実行時は遮断されているので `uv sync` で足すこともできない。

## Options

### Option A: 依存ゼロ核(stdlib only)
- Overview: 外部 SDK を使わず `urllib` で HTTP を直接叩き、JSON・`sqlite3`・`wave`・`html.parser` で通す。
- Cost: ゼロ。
- Security: 依存が増えないので供給網リスクが最小。
- Non-functional: 凍結環境を一切動かさない。ただしブラウザと mp3 デコードは結局イメージ外に残る。
- Implementation effort: リトライ・エラー分類・HTML パースを自作する分だけ増える。
- Pros / cons: 最も静的だが、mp3 デコードと形態素解析が原理的に解けない。

### Option B: 依存をイメージに焼く
- Overview: Containerfile で `uv sync --frozen` して venv を作り、ゲートをその venv の pytest へ向ける。
- Cost: イメージのビルド時間とサイズ。
- Security: イメージビルド時にはネットワークがあるので依存が入る。実行時は遮断のまま。
- Non-functional: 群1(純粋関数)に加え、mp3 デコード・形態素解析・ブラウザ E2E も `command` にできる。
- Implementation effort: D-019 / D-032 に同じことをやった先例がある。
- Pros / cons: 依存を変えるたびにイメージ再ビルドとダイジェスト再ピンが要る。

### Option C: 遅延 import + skipif でテストを飛ばす
- Overview: 依存を使うテストを `pytest.mark.skipif` で飛ばす。
- Pros / cons: **飛ばしたテストは証拠ではない**。「緑」が「走っていない」を意味する。要件はまさにその種の
  裏切りを潰してきたので整合しない。

## Decision

**Adopted**: Option B(依存をイメージに焼く)

**Reason**: 受入基準の多くが機械判定を要求しており、その判定に外部ライブラリが要る
(mp3 デコード、形態素解析、ブラウザ E2E)。Option A ではそれらが原理的に `command` 証拠にできず、
Option C は証拠を静かに空洞化させる。

## Consequences / results

- `.rein/oci/quiz-sift/Containerfile` に `uv sync --frozen` の層を足し、ffmpeg・fugashi + unidic・
  node + Playwright ブラウザを入れる。
- **依存を追加するたびにイメージ再ビルドと `config.yaml` のダイジェスト再ピンが要る**。これは凍結環境の
  変更なので、**mandate 承認前に済ませる**。承認後は `/revise` 案件。
- イメージが数百 MB〜1 GB 級になる。ビルド時間が `/tasks` の見積りに効く。
- **What this requires of a person**: 依存を1つ足すたびに `rein oci build --profile quality --write-config`
  を実行し、ダイジェストの変更をコミットすること。
- **Reversibility**: 可逆。Containerfile の変更を revert して再ビルドすれば戻る。
