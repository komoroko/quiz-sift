## Acceptance criteria

> 機械可読な写しは `.rein/plan.yaml` のこのタスクの `acceptance:` にあり、ループが読むのはそちら。
> **受入基準1本につきテストのノード ID を1つ割り当ててある**(タスクレビュー AR-1)。

- **A-1**: 任意の段階から再実行したとき、それより前の段階の外部 API 呼び出し回数が 0 になる。  
  判定: `pytest -q tests/pipeline/test_stage.py::test_rerun_makes_no_upstream_calls`
- **A-2**: inputs_digest が 前段成果物 + プロンプトテンプレート digest + モデル ID + 生成パラメータ から成り、ステージ実装コードは含まない。プロンプトを変えると digest が変わる。  
  判定: `pytest -q tests/pipeline/test_stage.py::test_digest_covers_prompt_and_model_but_not_code`
- **A-3**: ステージ出力が一時パスへ書かれ完了後に os.replace される。途中で落ちた実行の出力が次の実行にキャッシュヒットしない。  
  判定: `pytest -q tests/pipeline/test_stage.py::test_partial_write_does_not_become_a_cache_hit`

## Automated-test approach (the basis for the green decision)

- **Test kind**: unit / integration
- **Test file(s)**: `tests/pipeline/test_stage.py`
- **Test target / cases** — 各ノードについて **何を壊すと赤になるか**:

  - **A-1**: 再実行で前段をもう一度呼ぶ実装 → 赤
  - **A-2**: digest に前段成果物だけを入れる(プロンプトを変えても同じ digest)/ 実装コードまで入れる → 赤
  - **A-3**: 最終パスへ直接書く実装。途中で落とした後の再実行がキャッシュヒットする → 赤

> ノード ID は「その名前のテストが存在すること」までしか強制しない — **空の本体(`pass`)でも exit 0 になる**
> ことは実測で確かめてある。上の行は、実装者とレビュアーがその空白を見つけるための唯一の非循環な手掛かりで、
> 最終的な防御はタスク DoD の `review` ステップ(コードレビュアーがテストを読む)。
