# ADR-020: 複数正解問題のデータモデルと抽出(ADR-011 の一部を改める)

- **Status**: proposed
- **Date**: 2026-10-06
- **Decider**: human (finalized at the mandate)
- **Related requirements**: R-1、R-2、R-4、R-6、R-8、R-12

## Background / problem

前サイクルの `Question` は選択肢4件・正解1件(`correct_option_id`)を前提にしていた。実データ 190 問のうち 15 問(5択2正解 13、6択3正解 2)はこの前提に合わず、抽出の段で失敗として落ちていた。
入力形式・ドメイン・抽出・生成物・採点・UI のすべてが単一の正解を前提にしているので、どこまでを広げるかを決める必要がある。

## Options

### Option A: 全問を「ID の配列」に揃える(採用)
- Overview: `correct_option_ids: tuple[OptionId, ...]`(選択肢順・重複なし・1 ≤ N < M)。入力は `answers: [..]`。単一値の旧形式は拒否。
- Cost: 型の変更が src の約 12 ファイル・tests の 10 ファイル以上に波及する。
- Security: 影響なし。
- Non-functional: 単一正解も同じ経路を通るので、分岐が増えない。
- Implementation effort: 大(foundation タスク1本に集める)。
- Pros / cons: 二重実装が無い。後方互換を持たないので、旧形式の入力ファイルは作り直しが要る。

### Option B: 単一正解の型を残し、複数正解だけ別の型にする
- Overview: `correct_option_id` と `correct_option_ids` の併存。
- Cost: 変更は小さいが、全呼び出し側で分岐が要る。
- Pros / cons: 二重実装になる(作業規律2に反する)。

## Decision
**Adopted**: Option A

**Reason**: 人の回答(D-174 の範囲、D-176 の N 要素の答え、D-173 の完全一致)が全問で同じ形を前提にしている。

細目:
- 受け付ける範囲は M ∈ {4, 5, 6}、1 ≤ N < M(D-174)。範囲外、正解の配列が空・重複・未知 ID のものは理由付きで除外する。除外理由 `OPTION_COUNT_NOT_4` は `OPTION_COUNT_UNSUPPORTED` に改名(D-188)。
- 「N-of-M」は N ≥ 2 の問題を指す(G-2、D-199)。N = 1 は単一選択の UI のまま。
- 抽出: 正解マークが1件以上あれば全件を正解にする。マークが無い問題で受験者の選択から推定する経路は、ページの印(選択アイコンが単一選択の形)で単一選択と判別できた問題でだけ使い、判別できなければ抽出の失敗にする(D-189)。印は保存済みの生 HTML で確かめて決める。
- 生成物のプロンプトに渡す選択肢のキーは A〜F ではない不透明な値にし、R-6 のラベル判定に掛かる語を生成させない。

## Consequences / results
- 既存の `data/<deck>/*.jsonl` は読めなくなる。抽出由来のものは再抽出で作り直す。
- 抽出のゴールデンセットは集合ラベル(`A,C`)を受ける。

### What this requires of a person
- 前サイクルで保存した生 HTML がホストに残っていること。
- ゴールデンセットに加える N-of-M 3 件以上の正解を、人手で確かめてラベルを渡すこと。
- 手書きの入力ファイルがあれば新形式に直すこと。

### Reversibility
- コードと入力形式の変更は、コミットを戻せば元に戻る。
- 抽出のオフライン再抽出は可逆(保存済みの HTML を読むだけ)。人が Udemy から取り直す場合だけ不可逆(アカウントのアクセス履歴が残る)。これは ADR-025 の取り直しのタスクが扱う。
