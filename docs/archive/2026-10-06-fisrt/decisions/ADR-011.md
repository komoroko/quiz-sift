# ADR-011: 問題データは JSONL、デッキ manifest は YAML

- **Status**: accepted
- **Date**: 2026-09-22
- **Decider**: human (finalized at the mandate)
- **Related requirements**: R-1, R-2, R-11

## Background / problem

取り込みの入力形式は R-2 の出力形式でもあり、全フィクスチャがこれに乗る。
デッキ manifest は人が手で書くので、要求が違う。

## Options

### Option A: JSON Lines + JSON manifest
- Non-functional: stdlib で読める。行単位のエラー報告(R-1 の個別列挙)と相性がいい。
  manifest が JSON だとコメントが書けず、人が手で書くには窮屈。

### Option B: YAML で統一
- Non-functional: manifest は読みやすいが、問題データを YAML にすると行単位の処理ができない。
  PyYAML は mkdocs 経由でイメージに入っているが、暗黙依存になる。

### Option C: JSONL + YAML manifest
- Non-functional: 機械が書く問題データは JSONL、人が書く manifest は YAML。用途に合う。
  パーサが2系統になる。

## Decision

**Adopted**: Option C(JSONL + YAML manifest)

**Reason**: 「機械が書くもの」と「人が書くもの」で要求が違う。R-1 の「不正な問題を個別に列挙する」は
行単位の処理と相性がよく、manifest はコメントが書けることに価値がある。

## Consequences / results

- `data/<deck_id>/*.jsonl` が問題データ、`data/<deck_id>/deck.yaml` が manifest。
- manifest の項目: `deck_id`, `title`, `language`(`ja`/`en`)、`default_studied`。
- **PyYAML を `pyproject.toml` の明示的な依存として宣言する**。mkdocs 経由で偶然入っているものに
  依存しない。
- **デッキ ID は不変**とする。後から変えると学習記録のパーティションキーが動き、移行が要る。
- **What this requires of a person**: デッキごとに `deck.yaml` を書くこと。
  これが無いと D-015 の既習 / 初見の集計分離が達成できない。
- **Reversibility**: 可逆。ただし**全フィクスチャがこの形式に乗る**ので、変更すると
  フィクスチャの書き直しが要る。
