# ADR-015: 既定モデルは混成(分類・要約 = Opus 5 / 想起・用語・含意 = Haiku 4.5)

- **Status**: accepted
- **Date**: 2026-09-25
- **Decider**: human (finalized at the mandate)
- **Related requirements**: NFR-7, NFR-8, R-3, R-4, R-5, NFR-1

## Background / problem

ADR-013 が経路を CLI に移した結果、**呼び出し1回ごとに製品外の固定オーバーヘッドが乗る**
(実測: Opus 5 で 14,603 tok、Haiku 4.5 で 8,506 tok)。フル処理は 500〜1000 回の呼び出しに
なると見込まれるので、モデル選択がレート枠のリスクを直接左右する。

**2026-09-25 時点で、このアカウントの7日枠は既に 95% 使用済み**(`rate_limit_event` の実測。
5時間枠は 35%)。枠は有限であり、選択は仮説ではなく制約である。

## Options

| 軸 | A: Opus 5 全面 | B: Haiku 4.5 全面 | C: 混成 |
|---|---|---|---|
| 固定オーバーヘッド総量 | 7.3M〜14.6M tok | 4.3M〜8.5M tok | B に近い(呼び出しの大半が Haiku 側) |
| レート枠のリスク | 高い。バイナリ内に `Opus limit` という独立の文言が実在し、Opus が別枠で厳しい可能性がある | 最小 | 小。Opus 側は分類 4×2 + 要約 M で 10 数回に収まる |
| R-3 の分類精度 / NFR-1 の含意判定 | 最良(と期待。誰も比較していない) | 分類が粗くなり「その他」比率が上がる恐れ。NFR-1 の検出率に合格ラインが無い(D-044)ので、劣化はゲートに映らず人の目にしか出ない | 「圧縮の質」に効く分類・要約に Opus を残す |
| 工数 | 定数の置き換えのみ | 同左 | メソッドごとにモデルを引く。`Meter.record(model, usage)` は既にモデル別に積むのでそのまま乗る。単価表とオーバーヘッド定数を 2 モデル分持ち、測定も 2 回 |

Opus 5 が Pro プランで使えることは 2026-09-25 に実測で確認した(`is_error: false`)。

## Decision

**Adopted**: Option C(混成)。`classify_clusters` と `summarize_cluster` は `claude-opus-5`、
`generate_recall` / `describe_term` / `check_entailment` は `claude-haiku-4-5`。

**Reason**: 呼び出し回数の分布が極端に偏っている — 含意判定 350〜500 回・想起 175 回に対し、
分類は 4×2 回、要約はクラスタ数ぶん。**回数の 95% 以上を占める側を Haiku にすれば、トークン量で
測った枠の消費は Haiku 全面にほぼ等しい**まま、質が効く側に Opus を残せる。

**この論証の限界(AR-59)**: 上の一文は「枠の消費がトークン数に比例し、モデルに依らない」場合にだけ
成り立つ。**バイナリ内に `Opus limit` という独立の文言が実在する**以上 Opus には別枠がある可能性が
あり、その場合「呼び出しの 5% が Opus」は「Opus 枠の消費が 5%」を意味しない。**分類は最初の
ステージなので、Opus 枠に当たると後続の Haiku 呼び出しが1回も走らないまま止まる** — 混成は
「2つの枠のどちらに当たっても止まる」設計でもあり、これは Option C の短所である。モデルごとの
枠の重みは、**Opus と Haiku をそれぞれ数回叩いて前後の `rate_limit_event` の `utilization` 差を
読むだけで実測できる**(枠を使い切る必要がないので D-085 の凍結対象外)。`/tasks` の作業項目とする。

**数字の出所についての注記**: 14,603 / 8,506 tok と 3.4〜4.2 秒は `--output-format json`・ツール 28 本・
作業ディレクトリ非空の状態で測った値で、NFR-7 自身が「**(e) が存在しない時点の値であり、そのままでは
使えない**」と書いている。実際、(e) の argv では Haiku で 9,302 tok と別の値が出た。**この ADR の
定量的な比較と、D-100 の所要時間見積り(28〜70 分)は、取り直すまで暫定である。**

## Consequences / results

- NFR-7 の単価表とオーバーヘッド定数が 2 モデル分になる。**どちらも取得元を持つ**(AR-36)。
- オーバーヘッドの実測はモデルごとに3点(手順は `docs/20-design.md` の NFR-7 節)。**1ターンあたりの定数**として持つ(AR-57。成功1回でモデル往復が 2 回以上起きる)。
- モデル ID は `inputs_digest` に入る(`cli.py`)ので、**割り当てを変えると該当ステージのキャッシュが
  無効化される**。分類だけを Haiku に落とす変更は分類以降を全部再実行させる。
- **What this requires of a person**: なし(定数)。
- **Reversibility**: **可逆**。ただし切り替えは該当ステージの再実行(枠と時間を1回分)を意味する。
