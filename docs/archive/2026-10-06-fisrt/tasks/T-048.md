## To do

- `cli.py` にモジュール関数として伏せるフックを置き、`cli.main` が `sys.excepthook` をそれに差し替える。差し替えは `sys.excepthook` がそのフックと同一でないときだけ行う。
- フックは `traceback.format_exception` で原因の連鎖を含む全文を整形し、`mask_secrets` に通して、**呼ばれた時点の** `sys.stderr` へ書く。直前のフックは呼ばない。
- フックの中で例外が起きたら、例外の型名と「トレースバックを伏せた」旨だけを書き、例外を外へ出さない(フックが例外を出すと、インタプリタが元のトレースバックを平文で出すため)。
- 例外は捕まえない。`main` の外へそのまま抜けさせ、終了の仕方と `_exit_code` の対応は変えない。

scope: `src/quiz_sift/cli.py`, `tests/test_cli.py`

## Acceptance criteria

> 機械可読な写しは `.rein/plan.yaml` のこのタスクの `acceptance:` にあり、ループが読むのはそちら。

- **A-1**: 不具合の再現。合成の API キー・password・Cookie の値を載せた `ConnectionError` が、型を変えずに `cli.main` の外へ抜ける。`main` が返ったあとで `sys.stderr` を新しいバッファに差し替えてから、その例外情報で `sys.excepthook` を呼ぶ。新しいバッファには、型名と認証情報でないメッセージ部分が出て、合成値は平文で出ない。修正前は赤。  
  判定: `pytest -q tests/test_cli.py::test_uncaught_exception_traceback_masks_credentials`
- **A-2**: 認証情報を載せない例外の出力は、`traceback.format_exception` を連結したものと一致する。`raise X from Y` の原因側に載った値は伏せられ、連鎖表示は残る。  
  判定: `pytest -q tests/test_cli.py::test_excepthook_masks_the_cause_chain_and_changes_nothing_else`
- **A-3**: `main` を2回呼んだあとの `sys.excepthook` は、伏せるフックと同一である。別の関数に差し替えてから `main` を呼ぶと、伏せるフックに戻る。`main` の前に入っていたフックは呼ばれない。  
  判定: `pytest -q tests/test_cli.py::test_excepthook_is_installed_by_identity_and_does_not_delegate`
- **A-4**: `mask_secrets` が例外を出す状態でフックを呼んでも、フックは例外を外へ出さない。出力は型名だけで、合成値は平文で出ない。  
  判定: `pytest -q tests/test_cli.py::test_excepthook_failure_does_not_fall_back_to_plaintext`

- cli.py は T-037 → T-040 → T-048 → T-044 → T-045 の順に1タスクずつ編集する(AR-135 / AR-136)。
