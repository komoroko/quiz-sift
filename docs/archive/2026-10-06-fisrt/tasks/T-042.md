## Acceptance criteria

> 機械可読な写しは `.rein/plan.yaml` のこのタスクの `acceptance:` にあり、ループが読むのはそちら。

- **A-1**: 判定順序は 起動失敗(SPAWN)→ overage(PROVIDER_ERROR)→ TIMEOUT → PARSE → 許可集合外のツール(PROVIDER_ERROR。A-4)→ TRUNCATED → is_error(PROVIDER_ERROR)→ SCHEMA → INCOMPLETE_IDS である(D-156)。隣り合う2つの条件を同時に満たす入力(例: is_error が真かつ subtype が error_max_turns)は、それぞれ先の種別に落ちる。7種すべてに1件ずつ到達する入力がある。  
  判定: `pytest -q tests/adapters/test_claude_failure.py::test_classification_order_reaches_all_seven_kinds`
- **A-2**: TRUNCATED: subtype が error_max_turns の結果と、stop_reason が max_tokens / model_context_window_exceeded の結果は TRUNCATED になる。それ以外の stop_reason(end_turn / tool_use / 未知の値)は TRUNCATED にならない(D-120)。stop_reason / is_error / subtype は result イベントからだけ読む: assistant イベントが stop_reason: max_tokens を持っていても、success の result なら TRUNCATED にならない(D-131)。PARSE: stdout が result イベントをちょうど1つ含む JSON のイベント列にならない場合(空の stdout、JSON でない行、result の無い列、result が2つ)は、終了コードと stderr に関係なく PARSE になる。result を1つ持つ正常な stdout に exit 1 と stderr の 'Error:' が付いても PARSE にならない(D-119、AR-108)。SPAWN: spawn が例外を送出した場合だけ。再試行の経路は無い。  
  判定: `pytest -q tests/adapters/test_claude_failure.py::test_truncated_parse_and_spawn_inputs_land_in_their_kinds`
- **A-3**: overage の走査は、ストリーム全体の厳格なパースとは別に行う。stdout を行ごとに json.loads し、読めない行は飛ばす。isUsingOverage が真の rate_limit_event を含むストリームは、それ以外の点で success / TRUNCATED / SCHEMA / INCOMPLETE_IDS になるものでも PROVIDER_ERROR になる。JSON でない行を含み result の無いストリーム、タイムアウト時の途中の stdout でも同じく PROVIDER_ERROR になる。子1本について、最初と最後の RateLimitInfo(rate_limit_type / is_using_overage / overage_status を含む全フィールド)・届いた件数・overage が1回でも真だったかが取り出される。イベントが1件も無ければ最後の値は None で、resetsAt は記録されない(D-123、D-125、D-134)。  
  判定: `pytest -q tests/adapters/test_claude_failure.py::test_overage_scan_covers_parse_and_timeout_output`
- **A-4**: init イベントの tools が {StructuredOutput} と一致しない呼び出しと、stream-json の途中に StructuredOutput 以外の tool_use が現れた呼び出しは、失敗(PROVIDER_ERROR)になる。  
  判定: `pytest -q tests/adapters/test_claude_failure.py::test_tools_outside_the_allowlist_fail_the_call`
- **A-5**: InvocationRecord は次のフィールドを別々に持ち、ログはそのレンダリングとして出る: argv / exit_code / duration_sec / usage / failure_kind / result_is_error / rate_limit_first / rate_limit_last / rate_limit_event_count / overage_seen / stdin_sha256 / stdin_len / stdout_masked / stderr_masked。stdin の本文はどのフィールドにも入らない。合成の教材本文を含む stdout は、MaterialTextFilter でマスクされて出る。  
  判定: `pytest -q tests/safety/test_invocation_log.py::test_record_fields_are_separate_and_stdin_body_never_appears`
- **A-6**: secret_mask が、OAuth トークンの形(sk-ant-oat で始まる文字列)と .credentials.json のパス文字列をマスクする。マスクを外した実装に対して、このテストは赤になる。既存ノード test_credentials_and_cookies_are_masked(T-036 の凍結ノード)は消さず、名前も変えない(AR-153)。  
  判定: `pytest -q tests/safety/test_secret_mask.py::test_oauth_token_and_credentials_path_are_masked tests/safety/test_secret_mask.py::test_credentials_and_cookies_are_masked`
- **A-7**: このタスクのテストが使う stream-json のイベント列は、すべて tests/support/claude_fake.py の単一のファクトリから作られる。走査は同じファイルの関数 assert_no_inline_stream_json(tests_root) の1本で行う。対象は tests/ 配下の *.py のうち、tests/support/ と tests/measurements/ を除いたもの。キー "type" の値が system / assistant / user / result / rate_limit_event のいずれかである dict リテラル、またはそれを含む文字列リテラルが1つでもあれば赤。ファクトリは、成功フィクスチャの骨格から値だけを置き換えて次の形を作る: isUsingOverage が真、rate_limit_event を落とした形、status が rejected、7種それぞれの失敗。  
  判定: `pytest -q tests/adapters/test_claude_failure.py::test_event_streams_come_only_from_the_fake_factory`
