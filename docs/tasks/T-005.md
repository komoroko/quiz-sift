## Automated-test approach (the basis for the green decision)

- **Test kind**: unit / integration
- **Test file(s)**: `tests/store/test_concurrency.py`, `tests/store/test_deck_scope.py`, `tests/store/test_location.py`, `tests/store/test_schema.py`
- **Test target / cases** — 各ノードについて **何を壊すと赤になるか**:

  - **A-1**: store/ の外で sqlite3.connect を呼ぶ実装 → 赤
  - **A-2**: 生の接続を返す API / WHERE deck_id を落とした集計 → 赤
  - **A-3**: 起動時に1本開いた接続をハンドラスレッドで使い回す実装 → 赤
  - **A-4**: 所要時間 / セッション ID / 最終学習日時 / 誤答回数 のどれか1列を欠くスキーマ → 赤

> ノード ID は「その名前のテストが存在すること」までしか強制しない — **空の本体(`pass`)でも exit 0 になる**
> ことは実測で確かめてある。上の行は、実装者とレビュアーがその空白を見つけるための唯一の非循環な手掛かりで、
> 最終的な防御はタスク DoD の `review` ステップ(コードレビュアーがテストを読む)。
