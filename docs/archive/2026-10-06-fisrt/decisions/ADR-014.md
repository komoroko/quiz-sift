# ADR-014: 子プロセス境界の2分割と、最小ホームは人間が用意する

- **Status**: accepted
- **Date**: 2026-09-25
- **Decider**: human (finalized at the mandate)
- **Related requirements**: NFR-8, NFR-6, NFR-3, NFR-2

## Background / problem

NFR-8 は子プロセスの argv・env・作業ディレクトリ・起動中に作成されたファイルを機械判定せよと
要求し、NFR-6 は `claude` バイナリをサンドボックスイメージに焼かないと決めている。判定が成り立つ
境界の引き方と、NFR-8 (b) が要求する「最小ホーム」の用意方法を決める必要がある。

**(b) は NFR-3 と正面から衝突していた**。(b) は「最小ホームに資格情報を置く」と言い、NFR-3 は
AR-35 の処置として「本プロダクトはそのファイルを読まない・コピーしない」と定めている。「置く」の
主語が製品なら、製品は読むかコピーするしかない。

## Options(境界の引き方)

### Option A: runner が spawn だけを担う(2分割)
env 辞書の構築・argv の組み立て・空 cwd の作成・最小ホームの検証・stdout のパース・失敗分類・
マスクは**実コードのままサンドボックスで走る**。差し替えるのは `claude` の spawn だけ。

### Option B: runner が呼び出し全体を担う(1枚)
**却下**: (e)4 も (b) も「fake が観測した要求」しか検査できなくなり、実装の正しさが自己確認に落ちる
(AR-30 / AR-31 / AR-43 が3度指摘した形)。

## Options(最小ホーム)

### Option C: 人間が事前に用意し、製品は検証だけ
人間が `HOME=~/.quiz-sift-claude-home claude /login` を1回走らせて資格情報を作らせる。製品は
固定パスを `HOME` に渡し、起動時に `.claude/.credentials.json` が在ることだけを確かめる。
- Pros: NFR-3 と真正面から整合する(置くのは人間)。symlink の未実測を持ち込まない。実ホームの
  ログインと独立で、こちらのトークンが切れても本体は無傷。
- **Cons(採用案の短所。AR-58 の指摘により追記)**:
  - **資格情報は期限切れになるが、「ファイルが在る」検査ではそれが見えない**。28〜70 分のフル処理の
    途中で失効すると、そこから先の全呼び出しが `PROVIDER_ERROR` になり、D-101 により再試行されず、
    R-3 の「失敗があった実行は非 0 終了」で実行全体が捨てられる。
  - **固定パスはプロセス間で共有される可変資源**。2つの実行が同じ `.claude.json` を同時に書きうる
    (AR-64。設計はロックで直列化する)。Option D にはこの問題が無い。
  - 資格情報の長期コピーが実ホームに加えて**2箇所**になる。NFR-3 の「読まない・コピーしない」は
    満たすが、露出面は増える。
  - D-086 が `cleanupPeriodDays` を触らないと決めているので、**教材本文の平文がこのホームに
    無期限に蓄積する**。

### Option D: 使い捨てホーム + symlink
製品が呼び出しごとに `mkdtemp()` して資格情報へ symlink する。
- Pros: 人の手順が要らない。**固定パスの共有資源にならない**ので、プロセス間の競合(下記 Option C の
  短所)が原理的に起きない。**教材本文の平文コピーが蓄積しない**(呼び出しごとに消える)。
- Cons: Claude Code がトークン更新で書き戻すとき「一時ファイル + rename」なら symlink が実ファイルに
  置き換わり、**実ホームのログインが壊れうる**(未実測)。
- **却下**: 上の未実測のリスクが、実ホームの資格情報という**復旧に人の手が要る資源**に掛かるため。
  なお教材本文が消えることは D-088 が T-020 の不可逆ゲートの根拠に据えたものと干渉するが、
  **それは却下の理由にしない** — 不可逆ゲートは害を管理する仕組みであって、害を維持する理由にはならず、
  この論法を認めると平文コピーを減らすあらゆる改善が同じ理由で却下できてしまう。採るなら
  D-088 の根拠をレート枠の消費だけに差し替えればよい。

### Option E: OAuth トークンを環境変数で渡す
`claude setup-token` で発行し env で渡す。NFR-3 の「環境変数経由のみ」に最も筋が良い。
**却下**: NFR-8 (b) の許可集合が `HOME` / `PATH` / `LANG` / `TZ` の4つに固定されており、変数を
1つ増やすのは要件の書き換えになる。AR-30 の処置(許可集合の固定)が結果としてこの経路を塞いだ。
次サイクルで許可集合を見直すなら再検討に値する。

## Decision

**Adopted**: Option A(境界の2分割)+ **Option C(人間が事前に用意)**。

**Reason**: Option C は NFR-3 と真正面から整合する — **「置く」のは人間であり、製品は資格情報を
読みもコピーもせず、パスを渡して存在を確かめるだけ**。symlink の未知を持ち込まず、実ホームの
ログインとも独立なので、こちらのトークンが切れても本体は無傷。

**「最小ホームの内容が1ファイルだけ」の判定時点**は、**「製品が `HOME` 配下に作成したファイルが
0 件であること」**と読み替える。`claude` は `$HOME/.claude.json`・`.claude/projects/**/*.jsonl`
(D-086 が許容した教材本文の置き場そのもの)・`statsig/` を必ず書くため、文字どおりの「1ファイル
だけ」は2回目の起動から必ず偽になる。測りたいのは製品の振る舞いであって CLI の振る舞いではない。

## Consequences / results

- **2026-09-26 追記**: 起動時の検査は「`.credentials.json` が在ることだけ」から、[ADR-017](ADR-017.md) の**中身検査**(`.claude/CLAUDE.md`・`.claude/rules/` 配下・`settings.json` のキー集合)に置き換わった。子プロセスには `--safe-mode` が加わる。資格情報を開かない点は変わらない。

- `ports/process.py` に `CommandSpec`(`argv` / `env` / `cwd` / `stdin` / `timeout_sec`)・
  `CommandResult`・`CommandRunner` Protocol を置く。`CommandSpec` は `repr=False`
  (`stdin` が教材本文を持つため。AR-17 と同じ理由)。
- `adapters/claude_process.py` に `SubprocessRunner`(実 spawn)と `Workspace`
  (`new_cwd()` / `home()`)。`Workspace` はファイルシステムしか触らないので**ゲート内で実物が
  テストされる**。
- fake runner は監視ルートのファイル集合を `run()` 進入時に差分で取り、製品が作成した全ファイルに
  教材本文が現れないことを判定する(NFR-2 / AR-40)。
- **What this requires of a person**: **1回のセットアップ** —
  `HOME=~/.quiz-sift-claude-home claude /login`。これを忘れると起動時検査でエラー終了する
  (黙って実ホームへフォールバックしない)。
- **Reversibility**: **可逆**。ディレクトリを消せば戻る。実ホームの資格情報には触れないので、
  Option D が持っていた「ログインを壊す」経路が無い。
