> `/req` generates/updates this, sounding out from `docs/00-product-brief.md`.
> Finalized once a human approves at **the mandate**. Changes after approval need re-approval.

## Summary

前サイクル(`docs/archive/2026-10-06-fisrt/`)からの持ち越しを閉じ、入力を N-of-M の複数選択問題へ広げるデルタサイクル。
想起素材の段が実データで止まる不具合(DEF-1)とセキュリティの指摘 SEC-001〜SEC-004 を直し、実データ 190 問でフル処理を完走させる。
製品のバージョンを 0.1.1 にする。

`docs/00-product-brief.md` は入力を「4択」と書いているが、このサイクルの R-1 で M ∈ {4, 5, 6} に広げる(brief の文言は人が更新する)。想起素材は問題ごとに生成する(D-184)が、圧縮はクラスタリング(R-3)と、クラスタごとに束ねた台本・音声(R-4、R-6、R-7)で保つ。brief の「100問を100個の知識として扱わず」は、学習の単位がクラスタであることで満たす。

## このサイクルの読み方

- 要件の全文は前サイクルの [10-requirements.md](archive/2026-10-06-fisrt/10-requirements.md) にあり、ID(R-1〜R-12、R-9 は欠番。NFR-1〜NFR-8)をそのまま引き継ぐ。
- 下に見出しを持つ要件は、このサイクルで基準を**変える・足す**もの。見出しの中には差分だけを書く。書いていない基準は前サイクルのまま有効で、このサイクルの claim の対象ではない。
- 見出しの無い要件(R-5、R-10、R-11、NFR-3、NFR-4、NFR-6)は変更しない。R-10 の誤答率は R-8 の採点(完全一致)に従うので、文言も変わらない。
- Priority は着手順序であり、未達を許す指定ではない(前サイクルと同じ)。

## 用語の定義

### G-1: 実在

語句 t がテキスト s に**実在する**とは、次をすべて満たすことをいう。

1. t と s の両方を、NFKC 正規化 → 空白類の連続を1つに畳む → 前後の空白を除く → casefold の順で正規化する。
2. 正規化した t が、正規化した s の連続した部分文字列として現れる。
3. その出現の端で、t の端の文字が ASCII 英数字なら、その外側の文字は ASCII 英数字ではない。
4. 空の t はどこにも実在しない。

語形変化・同義語・語順の入れ替え・助詞の付け替えは実在とみなさない。この規則は現行の `grounding/presence.is_present` と同じであり、このサイクルでは規則そのものは変えず、**3つの検査が呼ぶ述語を1つに揃え、想起キーの照合先を問題文に絞る**。

照合先は検査ごとに次のとおり固定する。

| 検査 | 語句 | 照合先 |
|---|---|---|
| 想起キー(R-4) | キーの各語・状況・条件 | **その問題の問題文だけ**(選択肢と解説は含めない)。**このサイクルで変える** |
| 他クラスタ出現率(R-4) | キーの各語 | 他クラスタに属する問題の本文(問題文・選択肢・解説)。**変えない** |
| クラスタ要約(R-3) | 要約から切り出した専門用語の断片 | そのクラスタに属する問題の本文(問題文・選択肢・解説)。**変えない**(D-161) |

識別ポイントが参照する誤答選択肢は、テキストの照合ではなく、構造化した選択肢 ID で判定する(R-4)。

「照合先を揃える」とは、3つの検査が同じ述語を呼ぶことを指し、照合先を1つにすることではない。照合先を変えるのは想起キーだけで、他の2行は現行のまま(このサイクルの claim の対象外)。

### G-2: 複数正解問題

正解の件数 N が 2 以上の問題を**複数正解問題**と呼ぶ。この文書で「N-of-M」と書くときは複数正解問題を指す。N = 1 の問題は、選択肢が 5 件・6 件であっても単一正解問題であり、単一選択の UI と前サイクルの扱いのままとする。入力形式と生成物の形(正解を ID の配列で持つ、答えを N 要素の配列で持つ)だけは、N に関係なく全問で同じにする。

## List of things to achieve

### R-1: 問題データの取り込みと正規化
- **Overview**: 選択肢 M 件・正解 N 件の多肢選択問題(M ∈ {4, 5, 6}、1 ≤ N < M)を取り込む。4択・正解1件は N = 1、M = 4 の場合として扱う。
- **Background / why needed**: 実データ 190 問のうち 15 問(7.9%)が N-of-M(5択2正解が13問、6択3正解が2問)で、前サイクルは仕様として除外していた。
- **Priority**: Must
- **Acceptance criteria(差分)**:
  - [ ] 取り込んだすべての問題について、問題文・選択肢 M 件・正解 N 件が欠落なく保持される。
  - [ ] (N, M) が上の範囲の外にある問題、正解が特定できない問題、ID が重複する問題は、問題ごとに列挙され、除外件数が報告される。
  - [ ] 正常系のフィクスチャは、範囲内の (N, M) の 12 組すべて(M=4 で N=1〜3、M=5 で N=1〜4、M=6 で N=1〜5)をそれぞれ1問以上含み、それに対する除外件数が 0 になる。範囲外のフィクスチャ(M=3、M=7、N=0、N=M)はすべて除外される。
  - [ ] 正解の配列が空、ID が重複する、選択肢に無い ID を含む問題は「正解が特定できない」として除外する。
  - [ ] 入力形式の正解は選択肢 ID の配列1つで表す。正解を単一の値で持つ旧形式は受け付けない(後方互換は持たない)。
- **How verified**: 受入テスト(合成フィクスチャ)。

### R-2: Udemy からの問題自動抽出
- **Overview**: 正解のマークが N 件付いた問題を、N 件の正解として抽出する。
- **Background / why needed**: N-of-M の15問は取り込みより手前、抽出の段で選択肢の失敗として落ちている(`archive/2026-10-06-fisrt/test/measurements/extraction-run.md`)。抽出を直さないと、実データに N-of-M は現れない。
- **Priority**: Must
- **Acceptance criteria(差分)**:
  - [ ] 選択肢が5件・6件の問題ブロックを抽出の失敗にしない。選択肢が 3 件以下・7 件以上のブロックは、抽出の失敗として列挙する。
  - [ ] 正解のマークが N 件ある問題を、N 件の正解として抽出する。
  - [ ] 受験者の選択から正解を推定する経路(正解マークが無い問題で受験者の選択を正解とする)は、ページの印(選択アイコンが単一選択の形か複数選択の形か)で**単一選択と判別できた問題でだけ**使う。複数選択と判別した問題、判別できなかった問題で正解マークが無いものは、抽出の失敗として列挙する。判別に使う印は、保存済みの生 HTML で確かめてから決める。
  - [ ] ゴールデンセットに、人手で正解を確認した N-of-M の問題を3件以上加え、加えた後のゴールデンセット全体で、抽出した正解の集合の一致率が 100% である。
  - [ ] 実デッキは、まず前サイクルの取得で保存した生 HTML を新しい抽出器でオフラインに再抽出する(可逆)。再抽出の報告に、全問数・(N, M) の組ごとの件数・抽出の失敗の件数が現れる。
  - [ ] 期待する件数は、前サイクルの実測から全 190 問、うち 5択2正解 13 問・6択3正解 2 問。再抽出がこれに届かない場合に限り、**人が** Udemy にログインして実デッキを取り直す(不可逆、試行 1 回)。取り直しても届かなければ、届かなかった件数と理由を記録し、フル処理は得られたデッキで行う。
- **How verified**: 受入テスト(ゴールデンセット)と、再抽出(必要なら取り直し)の記録(`artifact`)。

### R-3: 類似問題のクラスタリング(圧縮)
- **Priority**: Must
- **Acceptance criteria(差分)**:
  - [ ] 呼び出し1回ごとのタイムアウトが、子プロセスの子(孫)が stdout と stderr の pipe を持ち続けても効く。超過したときはプロセスグループごと終了させ、タイムアウトから 10 秒以内に `TIMEOUT` として返る(SEC-004)。孫が自分で新しいセッションを作った場合(`setsid`)でも、pipe の読み取りを打ち切って 10 秒以内に戻る(そのような孫を終了させることまでは求めない)。
- **How verified**: pipe を継承した孫を残す fake の子プロセスで、上限時間内に戻ることを確かめる受入テスト。修正前のコードで赤になること。
- 実データでの M/N・比率・再現性の記録は、フル処理(NFR-7)で取る。

### R-4: 想起素材の生成
- **Overview**: 各問題について「想起キー」「その手がかりに対する答え」「紛らわしい選択肢との識別ポイント」を生成し、クラスタごとに束ねる(前サイクルの「各クラスタについて」を、実装と照合先に合わせて書き直す)。
- **Background / why needed**: 実データの列で想起素材の段が全件拒否された(ungrounded_keys 175/175、missing_options 47)。生成プロンプトと検査がそれぞれ別の「実在」を前提にしていたのが原因。
- **Priority**: Must
- **Acceptance criteria(差分)**:
  - [ ] 想起キーの各語・状況・条件が、G-1 の意味で、**その問題の問題文**に実在する。
  - [ ] 想起キーの検査・他クラスタ出現率・クラスタ要約の検査は、G-1 を実装した述語1つを呼ぶ。生成プロンプトが指示する照合先は、検査が使う定数から組み立てる。どちらか片方だけを変えるとテストが赤になる。
  - [ ] 識別ポイントは、参照する誤答選択肢をテキストの括弧ではなく**構造化した選択肢 ID の列**で示す。各識別ポイントが1件以上を参照し、参照した ID はすべてその問題の誤答選択肢(正解の集合に含まれない選択肢)である。本文中の括弧は検査しない。
  - [ ] 答えは N 要素の配列で、各要素は対応する正解の**選択肢 ID** を持つ。要素の ID の集合が正解の ID の集合と一致しなければ(要素数の不足・超過、重複、正解でない ID)検査で落とす。要素と正解の対応は ID で取り、配列の順序には意味を持たせない。
  - [ ] 重複キーの検査は、要件の文面(同一の想起キーが複数の**クラスタ**で使われていない)どおり、異なるクラスタの素材の間だけで数える。現行の `recall/verify.duplicate_count` は同じクラスタ内の問題どうしも数えており、要件より強い。
  - [ ] 識別ポイントの含意判定では、reference に、その識別ポイントが参照する誤答選択肢の本文を加える。本文が参照先の誤答選択肢と矛盾すれば、NFR-1 と同じく成果物を出さずにエラー終了する。
  - [ ] 再生成の対象は、1問単位の検査(実在しないキー、汎用語キー、丸写し、選択肢 ID の不整合、答えの要素の不整合、空の要素)と、クラスタをまたぐ重複キー(クラスタ順で後に来た問題を作り直す)と、含意判定の不合格(NFR-1。機械検査を通った素材だけを判定する)に限り、同じ上限の中でその問題だけを再生成する(D-232、ADR-026。D-191 を改める)。LLM 呼び出しの失敗(TIMEOUT など)は再生成しない(前サイクルの D-101 のまま)。
  - [ ] 検査に落ちた問題は、**その問題だけを**上限 2 回まで再生成する。問題ごとの再生成回数を記録し、上限を超えた問題が1件でもあれば成果物を出さずに非 0 終了する。再生成の呼び出しも `llm_calls` と `provider_invocations` に数える。
  - [ ] 合成デッキ(日本語と英語を含み、複数正解問題を含む)を実 CLI で recall 段まで通すと、recall 段が exit 0 で終わり、想起素材の検査のすべての件数(ungrounded_keys、generic_keys、duplicate_keys、verbatim、選択肢 ID の不整合、答えの要素の不整合)が 0 で、含意判定が通り、問題ごとの再生成回数とレート枠の使用率が記録される(フル処理の前に置く可逆なリハーサル)。
- **How verified**: 受入テスト(fake の LLM)と、合成デッキのホスト実測(`artifact`)。実データでの完走はフル処理(NFR-7)。
- **想起キーの定義**: 問題文に現れ、その問題の正解を一意に指し示す語・状況・条件の組(D-005 を、生成単位に合わせて「クラスタ」から「問題」へ読み替える)。

### R-6: 音声学習用台本の生成
- **Priority**: Must
- **Acceptance criteria(差分)**:
  - [ ] ラベル列挙の判定を、4件固定からその問題の M 件に広げる。記号 A〜F・番号 1〜6・かな ア〜カのいずれであれ、同じ系列の先頭から M 件のラベルが**すべて**揃う形(日本語はトラック内に揃う、英語は区切りで連なる。現行 `script/label_guard` の判定のまま)を、ラベル列挙とする。判定はトラック単位なので、M には**そのトラックに含まれる問題の M の最小値**を使う。それより少ないラベルの言及はラベル列挙としない。
  - [ ] N-of-M の問題では、台本の「答え」が正解 N 件すべてに言及する。R-4 の N 要素の答えから組み立て、要素の欠けた台本は出さない。
- **How verified**: 受入テスト。

### R-7: 音声ファイルの生成と書き出し
- **Priority**: Must
- **Acceptance criteria(差分)**:
  - [ ] フル処理の列で、実 CosyVoice(torch 2.10)で生成した全クラスタの音声について、前サイクルの無音判定(先頭と末尾を除く位置に、前後を有音区間に挟まれた3秒以上の無音)が真である。
- **How verified**: フル処理の記録(`artifact`)。

### R-8: 事前/事後テストの出題と学習記録
- **Overview**: 元の多肢選択問題を出題し、選んだ選択肢の集合・正誤・所要時間を記録する。
- **Priority**: Must
- **Acceptance criteria(差分)**:
  - [ ] 問題ごとに、選んだ選択肢の**集合**・正誤・所要時間が永続記録される。
  - [ ] 選んだ集合が正解の集合と**完全に一致したときだけ**正答とする。部分点は付けない。
  - [ ] UI と API は、ちょうど N 件を選んだときだけ回答を受け付ける。API は N 件以外の回答を 400 で拒否する。
  - [ ] シャッフル提示の下での 100% / 0% の基準を、N-of-M を含むフィクスチャで満たす。誤答の入力は、正解の集合と一致しない N 件の集合(正解の1件を誤答選択肢1件に入れ替えたもの)で作る。
  - [ ] 学習記録ストアは新しい形で作り直す。ストアの所在(パス)は変えず、その所在に旧形式のストアを見つけたら、黙って読み替えずにエラーで止まる。旧形式からの移行は作らない(残す記録が無いことを人が確認済み)。
- **How verified**: 受入テスト。

### R-12: Web UI
- **Priority**: Must
- **Acceptance criteria(差分)**:
  - [ ] N-of-M の問題は複数選択の UI で出題し、「N 個選択」を表示する。選択がちょうど N 件のときだけ回答を送れる(N 件未満でも N+1 件以上でも送れない)。
- **How verified**: UI の e2e(`artifact`、前サイクルの ADR-012 と同じ判定)。

## Non-functional requirements (criteria)

### NFR-1: 誤学習の防止
- **Criterion (measurable)(差分)**:
  - 対象は想起素材・台本・クラスタ要約の含意判定。グロッサリ(R-5)の reference は前サイクルのまま(公式解説)で、この差分の対象外。
  - 含意判定の reference が、正解 N 件すべてを含む。識別ポイントの reference は、加えて参照先の誤答選択肢の本文を含む(R-4)。
  - N 要素の答え(R-4)は、要素ごとに、その要素が持つ選択肢 ID の正解の選択肢と含意判定にかける(配列の位置では対応を取らない)。
  - N 件のうち1件とだけ矛盾する生成物は成果物に書かない。想起素材・クラスタ要約・グロッサリの説明は、矛盾した項目だけを上限 2 回まで作り直し、上限を超えたら成果物を出さずにエラー終了する。台本は文を生成しないので作り直さず、矛盾すればエラー終了する(D-232、ADR-026)。
  - 正解を言い換えただけの正しい生成物で誤検出しない((b) を N-of-M にも適用する)。
- **How verified**: 受入テスト(スタブの判定器と、矛盾・言い換えのフィクスチャ)。

### NFR-2: 教材データの保護
- **Criterion (measurable)(差分)**:
  - 子プロセス(`claude`)の stdout と stderr の**本文**とその断片が、ログの流れ(stderr と、**すべてのレベル**のログ。例外のメッセージを経由してログに出るものを含む)に 0 件である(SEC-003)。
  - 子の呼び出し1回の記録として出すのは、構造化した項目(argv、終了コード、所要時間、4値トークン、失敗種別、レート枠、stdin のダイジェスト、`init.tools`、`isUsingOverage`)だけにする。この制限は子の呼び出しの記録に掛かり、本文を含まない製品自身の集計行(`run_id`、`llm_calls` などの NFR-7 の記録、段ごとの件数)は対象外。
  - 子の出力本文から作った値(未知の判定語など)は、例外のメッセージにもログにも載せない。診断のために本文を別のファイルへ残すこともしない(診断が要るときは、合成の入力での再現を試みる。実教材を手で CLI に流すことはしない)。
  - 前サイクルの「マスク後に残る言い換えテキストを許容する」(D-097)を**覆す**。DEF-1 の修正で問題文の逐語の断片が想起キーとして子の出力に載るようになり、登録した文字列全体しか伏せないマスクでは漏れるため。
  - マスク後のログに必須の項目が残ること(AR-42)は変えない。
- **How verified**: 番兵の本文を返す fake の子プロセスで、ログの流れに番兵が 0 件、必須の項目がすべて残ることを確かめる受入テスト。番兵は成功応答だけでなく、SCHEMA・PARSE・TIMEOUT・未知の判定語の各失敗経路でも流す。

### NFR-5: 開発基盤と CI
- **Criterion (measurable)(差分)**: 製品のバージョンが 0.1.1 で、`pyproject.toml` の version、`quiz_sift.__version__`、`uv.lock` の quiz-sift の項目、`--version` の出力の4か所で一致する。src・tests・`pyproject.toml` と `uv.lock` の quiz-sift の項目に、quiz-sift のバージョンとしての `0.1.0` が残らない(依存パッケージのバージョンと docs は対象外)。
- **How verified**: 受入テストと品質ゲートの smoke ステップ。

### NFR-7: 処理コストと所要時間の可視化(フル処理の完走)
- **Criterion (measurable)(差分)**:
  - **固定オーバーヘッドを、このサイクルの argv で取り直す。** NFR-8 の変更で argv が変わると、前サイクルの較正値はそのままでは使えない。前サイクルと同じ方法(既知長の合成プロンプト k = 1, 2, 3 の3点、差と切片の判定)で、ホストで実測する。NFR-8 (b)(e)1 の実測で argv が確定した**後**、フル処理の前に置く。較正の記録には、使った argv を残す。

### NFR-8: 外部サービスの利用が従量課金を伴わないこと
- **Criterion (measurable)(差分)**:
  - **(b) 子の CLI にユーザ設定を読ませない**(SEC-001)。子の CLI に、ユーザ設定を読まない指定を渡す。起動前の中身検査(前サイクルの (b) の 1〜3)は残す。
    - 実測は、中身検査を通さず実 CLI を直接起動して行う(製品の経路では、番兵を置いた設定は中身検査が起動前に止めるので、番兵が現れないことが指定の効果の証拠にならない)。前サイクルの home-probe と同じく、最小ホームの `.claude/settings.json` を一時的に書き換え、終わったら元のバイト列の sha256 の一致で戻ったことを確かめる。その `.claude/settings.json` に、読まれると呼び出しが失敗する番兵の `env`(到達できない `ANTHROPIC_BASE_URL` など)を置き、製品と同じ argv で、指定を**付けない**起動では呼び出しが失敗し(陰性対照)、指定を**付けた**起動では成功することを確かめる。陰性対照の失敗は、番兵のアドレスへの接続の失敗であることを stderr の分類で確かめる。実測の argv は製品の `build_argv` が返すものと一致することを機械判定する。
  - **(e)1 有効ツールを許可リストで指定する**(SEC-002)。有効ツールを `{"StructuredOutput"}` の許可リストとして argv で指定し、**拒否リストを argv から外した状態で** `init.tools` がそれと一致することをホストの実 CLI で確かめる。権限の自動承認の指定(`--allowedTools` など)は、ツールの有効化の指定ではないので許可リストに数えない。空の許可リスト(StructuredOutput は CLI が差し込む)も、`init.tools` が一致すれば許可リストに数える。
    - 試す指定は、実 CLI の `--help` に現れる、有効ツールを列挙する形のフラグすべて。どれでも一致しなかった場合に限り、拒否リストのまま `init.tools` の一致判定を残し、試したフラグごとの `init.tools` の実測を記録に残す。
  - **(a) 従量課金の SDK の経路を消す。** 製品の経路に無い `adapters/llm_anthropic.py` を削除する。前サイクルの (a)(既定構成の実行が SDK を読み込まない)のテストは弱めずに残し、消えたアダプタに代わる陰性対照(anthropic を import する合成のアダプタを差し込むと赤)を付ける。依存 `anthropic` を `pyproject.toml` と `uv.lock` から外すのは、品質ゲートのイメージの作り直しと再ピンが要るので次サイクルに繰り越す(D-223)。
- **How verified**: argv の形の受入テスト(fake runner)と、ホストでの実 CLI の実測(`artifact`)。(a) は依存の一覧と import の検査の受入テスト。
