## To do

- `pyproject.toml` の `[tool.uv]` に `constraint-dependencies = ["setuptools>=83"]` を足す。
- `uv lock` で解決し直す。
  - dry-run の見込みは次のとおり。
    - setuptools: 81.0.0 → 84.0.0
    - torch: 2.11.0+cu128 → 2.10.0+cu128(torchaudio も同じ系)
    - nvidia-cudnn-cu12・nvidia-nccl-cu12・cuda-bindings の版が変わり、cuda-toolkit は外れる。
  - ほかのパッケージの版は変えない(`--upgrade` を付けない)。
  - `exclude-newer = "1 week"` はそのまま残す。
- `tests/test_dependencies.py` を新しく作る。`pyproject.toml` と `uv.lock` を `tomllib` で読み、A-1 を確かめる。
- `.rein/oci/quiz-sift/requirements.txt` は変えない。extra を含まないので、torch と setuptools は入っていない。

scope: `pyproject.toml`、`uv.lock`、`tests/test_dependencies.py`

## Acceptance criteria

> 機械可読な写しは `.rein/plan.yaml` のこのタスクの `acceptance:` にあり、ループが読むのはそちら。

- **A-1**: 制約 `setuptools>=83` がある。lock の setuptools は 83 以上で、torch と torchaudio は 2.10 系の +cu128。修正前は赤。  
  判定: `pytest -q tests/test_dependencies.py::test_setuptools_is_constrained_to_the_fixed_version`
- **A-2**: イメージに焼く requirements.txt が lock と一致したまま。  
  判定: `pytest -q tests/test_gate_environment.py::test_baked_requirements_match_the_lockfile`
- **A-3**: lock の変更は setuptools・torch・torchaudio と、連動する CUDA 系だけに留まる(レビューで差分を見る)。

## Notes / design decisions

- 2026-09-29 の監査で、setuptools 81.0.0 に PYSEC-2026-3447 が見つかった(修正は 83.0.0)。
- torch 2.11 が `setuptools<82` を要求するので、setuptools を上げると torch は 2.10 に下がる。
- torch 2.10 で実際の TTS(CosyVoice)が動くかは、本サイクルでは確かめられない。次サイクルのフル処理(元の T-047)で確かめる。
