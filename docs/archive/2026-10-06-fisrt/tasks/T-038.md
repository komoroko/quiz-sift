## Acceptance criteria

> 機械可読な写しは `.rein/plan.yaml` のこのタスクの `acceptance:` にあり、ループが読むのはそちら。

- **A-1**: 手で組んだ3実行ぶんの開始行・終了行に対する集約で、次の値が手計算の期待値と一致する。和: llm_calls / provider_invocations / model_turns / turns_by_model / tokens / tokens_by_model / invocations_without_usage / invocations_without_turns / failures_by_kind / overage_invocations / invocations_without_rate_limit_event。最大: max_concurrency。時間: elapsed_sec_sum と wall_clock_sec。estimated_cost: computed と declared はそれぞれ和で、relative_diff は和から計算し直す。status: recorded はすべての実行が recorded のときだけで、notional: true と disclaimer が付く。レート枠: quota(実行ごとの {execution_id, at_start, at_end})と quota_missing。overage_check は和から判定する。metered_env_names は和集合。  
  判定: `pytest -q tests/pipeline/test_run_sequence.py::test_aggregate_sums_max_and_times`
- **A-2**: 列の status と not_completable_reasons が次の表のとおりになる(D-145)。completed: fresh → レート枠で停止 → resume で audio を exit 0。resumable: 最後の実行がレート枠で停止した列、最後が recall で exit 0 の列。not_completable: 最初の実行が fresh でない、途中の実行が非 0 でレート枠による停止でない(ended_by_rate_limit が偽)、overage_invocations > 0、metered_env_names が空でない実行がある、閉じていない開始行(いま締めている実行を除く)がある、のそれぞれ。存在しない run_id を問い合わせるとエラーになる。  
  判定: `pytest -q tests/pipeline/test_run_sequence.py::test_status_table`
- **A-3**: JSON として読めない行が、その列の最初の開始行より後ろにあれば、列は not_completable(理由 unreadable_line:<行番号>)になる。前にあれば unreadable_lines_before に数えるだけで、status は変わらない。どちらも例外にしない。対象 run_id の行で、既知の形でないもの(必須キーの欠落)は例外で止まる。  
  判定: `pytest -q tests/pipeline/test_run_sequence.py::test_unreadable_lines`
- **A-4**: Meter.finish が書く終了行に sequence がある。その値は、ファイル上の同じ run_id の行と、いま書く終了行を合わせた集約に等しく、いま締めている実行の開始行は閉じていないものに数えない。tests/pipeline/test_meter.py の終了行キーのリテラルに sequence が加わる(D-139)。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_end_line_carries_the_sequence_aggregate tests/pipeline/test_meter.py::test_start_and_end_lines_carry_the_design_fields`
