## To do

`adapters/claude_failure.py` に stream-json のイベント列を読む判定表と判定順序を、`safety/invocation_log.py` に
`InvocationRecord` とそのレンダリングを置き、`safety/secret_mask.py` に OAuth トークンの形と `.credentials.json` の
パス文字列を足す。

- 判定順序: 起動失敗 → タイムアウト → `PARSE` → `TRUNCATED`(`subtype` が `error_max_turns`、または `stop_reason` が切り詰め。D-102)
  → `PROVIDER_ERROR`(`is_error` が真)→ `SCHEMA` → `INCOMPLETE_IDS`。
- レート制限は特別扱いしない(D-091 撤回)。最後に観測した `rate_limit_info` の `status` と `resetsAt` を失敗の記録に残す。
  `ended_by_rate_limit` の真偽は D-110。
- `init.tools` が `{"StructuredOutput"}` と一致しない、または途中に許容外の `tool_use` が現れたら `PROVIDER_ERROR`(D-106)。
- `InvocationRecord` はフィールドを分けて持ち、ログはそのレンダリングとして作る(全文を後からマスクする実装にしない。AR-42)。
  stdin は `stdin_sha256` と `stdin_len` だけ。stdout / stderr は既存の `MaterialTextFilter.mask` を通す。

scope: `src/quiz_sift/adapters/claude_failure.py`, `src/quiz_sift/safety/invocation_log.py`, `src/quiz_sift/safety/secret_mask.py`, `tests/adapters/test_claude_failure.py`, `tests/safety/test_invocation_log.py`, `tests/safety/test_secret_mask.py`, `tests/support/`

## Acceptance criteria

> 機械可読な写しは `.rein/plan.yaml` のこのタスクの `acceptance:` にあり、ループが読むのはそちら。

- **A-1**: 判定順序が 起動失敗 → タイムアウト → PARSE → TRUNCATED → PROVIDER_ERROR → SCHEMA → INCOMPLETE_IDS であり、2つの条件を同時に満たす入力(例: is_error が真かつ subtype が error_max_turns)がそれぞれ先の種別に落ちる。7種すべてに1件ずつ到達する入力がある。  
  判定: `pytest -q tests/adapters/test_claude_failure.py::test_classification_order_reaches_all_seven_kinds`
- **A-2**: subtype が error_max_turns の結果は TRUNCATED、JSON でない stdout は PARSE、rate_limit_event を伴って is_error が真の結果は PROVIDER_ERROR に落ち、最後に観測した rate_limit_info の status と resetsAt が失敗の記録に残る。レート制限を再試行する経路が無い。  
  判定: `pytest -q tests/adapters/test_claude_failure.py::test_rate_limit_is_a_provider_error_with_resets_at`
- **A-3**: init イベントの tools が {StructuredOutput} と一致しない呼び出し、および stream-json の途中に StructuredOutput 以外の tool_use が現れた呼び出しは失敗(PROVIDER_ERROR)になる。  
  判定: `pytest -q tests/adapters/test_claude_failure.py::test_tools_outside_the_allowlist_fail_the_call`
- **A-4**: InvocationRecord が argv / exit_code / duration_sec / usage / failure_kind / rate_limited / rate_limit_evidence / stdin_sha256 / stdin_len / stdout_masked / stderr_masked を別フィールドで持ち、ログはそのレンダリングとして出る。stdin の本文はどのフィールドにも入らない。合成の教材本文を含む stdout は MaterialTextFilter でマスクされて出る。  
  判定: `pytest -q tests/safety/test_invocation_log.py::test_record_fields_are_separate_and_stdin_body_never_appears`
- **A-5**: secret_mask が OAuth トークンの形(sk-ant-oat で始まる文字列)と .credentials.json のパス文字列をマスクする。マスクを外した実装に対してこのテストが赤になる。  
  判定: `pytest -q tests/safety/test_secret_mask.py::test_oauth_token_and_credentials_path_are_masked`
- **A-6**: T-026 のテストが使う stream-json のイベント列は、すべて tests/support/claude_fake.py の単一のファクトリから作られる。走査は tests/support/claude_fake.py の関数 assert_no_inline_stream_json(tests_root) の1本で行い、その定義は次のとおり: 対象は tests/ 配下の *.py のうち tests/support/ と tests/measurements/ を除いたもの。キー "type" の値が system / assistant / user / result / rate_limit_event のいずれかである dict リテラル、またはそれを含む文字列リテラルが1つでもあれば赤。tests/fixtures/ の .stdout は *.py ではないので対象外。 この関数は T-026 が置き、T-027 A-6 も同じ関数を呼ぶ。  
  判定: `pytest -q tests/adapters/test_claude_failure.py::test_event_streams_come_only_from_the_fake_factory`
