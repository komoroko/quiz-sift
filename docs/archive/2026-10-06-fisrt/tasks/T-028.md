## To do

既定 LLM を Claude Code CLI へ切り替える**カットオーバー**。旧経路の撤去はこのタスクだけで行う。

- `src/quiz_sift/composition.py` を新設し、`build_default_llm(meter: RunMeter) -> Llm: return ClaudeCliLlm(meter)` だけを置く。
- `cli.py`: `from quiz_sift.adapters import llm_anthropic` を削除し、`inputs_digest` 用の定数は `llm_prompts` から読む。
  `LlmFactory = Callable[[RunMeter], Llm]`、既定は `composition.build_default_llm`。フル処理の開始時と終了時に
  LLM を使う段の前に `claude_process.preflight()`(D-115)。実経過時間の上限(既定 12 時間)。各段の `inputs_digest` にその段のモデル ID を入れる。
  `_default_llm` は削除する。レート枠の記録はアダプタ側(D-114)。
- `llm_anthropic.py`: `AnthropicLlm(meter)` の1引数にし、クライアントは本体で構築する(negative control のため。AR-55)。
- `pyproject.toml`: `[project.scripts]` を1本だけ足す(`quiz-sift = "quiz_sift.cli:main"`)。**`anthropic` は通常依存のまま**
  (D-103)。
- `tests/nfr8/`: (a) を新規インタプリタで判定(sys.path にスタブの `anthropic`、PATH に fake の `claude` 実行ファイル、
  tmp の HOME に最小ホームの形、親環境に 13 個の metered 認証変数)、positive / negative control、(c) の AST、
  (d) の import グラフ走査(コンソールスクリプトと `__main__` ガードを持つモジュールすべて。`server/__main__.py` を含む)。

scope: `src/quiz_sift/composition.py`, `src/quiz_sift/cli.py`, `src/quiz_sift/adapters/llm_anthropic.py`, `pyproject.toml`, `uv.lock`, `tests/nfr8/`, `tests/test_cli.py`, `tests/ports/test_protocols.py`, `tests/safety/test_entailment.py`, `tests/support/`

## Acceptance criteria

> 機械可読な写しは `.rein/plan.yaml` のこのタスクの `acceptance:` にあり、ループが読むのはそちら。

- **A-1**: 新規インタプリタで、親環境に 13 個の metered 認証変数を入れ sys.path にスタブの anthropic パッケージを置いた状態で、既定構成のクラスタリング段を1回走らせた後、sys.modules に anthropic が無く、同じ実行で build_default_llm() が呼ばれ llm_calls ≥ 1 である(positive control)。anthropic が import できなければ skip せず失敗する。claude は PATH に置いた fake 実行ファイル、最小ホームはテストが作った tmp の HOME で満たす。  
  判定: `pytest -q tests/nfr8/test_no_metered_sdk.py::test_default_run_never_loads_the_sdk`
- **A-2**: 選択点を SDK アダプタへ差し替えた版で同じ判定が赤になり、その差し替え版でも llm_calls ≥ 1 が緑である(negative control。import だけで赤になったのではないことを示す)。AnthropicLlm のコンストラクタは (meter) の1引数で、クライアントは本体で構築する。  
  判定: `pytest -q tests/nfr8/test_no_metered_sdk.py::test_swapping_in_the_sdk_adapter_goes_red`
- **A-3**: composition.build_default_llm の本体が return 文1つで、右辺が inspect.isclass で確かめたクラス名の直接呼び出しであり、If / Match / Try / Subscript / IfExp / BoolOp / Lambda / Attribute / comprehension / Import を含まない。src/ 全体で Llm を実装するクラスを構築する式が composition.py の1箇所だけである。  
  判定: `pytest -q tests/nfr8/test_composition.py::test_single_static_selection_point`
- **A-4**: pyproject.toml のコンソールスクリプトがちょうど1つで、それと __main__ ガードを持つモジュール(python -m の入口)すべてから到達可能な import グラフに、anthropic など metered API へ HTTP を発行しうるモジュールが 0 件である。cli.py は llm_anthropic を import しない。  
  判定: `pytest -q tests/nfr8/test_entry_points.py::test_no_entry_point_reaches_a_metered_client`
- **A-5**: LlmFactory が Callable[[RunMeter], Llm] になり、LLM を使う段は最初の LLM 呼び出しより前に claude_process.preflight() を通し、PATH に claude が無い、または最小ホームが不正なら LLM を1回も呼ばずに非 0 で終わる。外部 LLM 呼び出しに失敗があった実行は下流へ進まず非 0 で終わり、サマリに未分類比率・最大クラスタ比率・失敗件数が出る。実経過時間が上限(既定 12 時間)を超えた実行も非 0 で終わる。  
  判定: `pytest -q tests/test_cli.py::test_llm_stages_meter_quota_and_stop_on_failure`
- **A-6**: 各段の inputs_digest に、その段で使うメソッドのモデル ID(ADR-015 の割り当て)が入る。ある段のモデルだけを変えるとその段の digest が変わり、キャッシュが無効化される。  
  判定: `pytest -q tests/test_cli.py::test_stage_digest_carries_the_models_it_uses`
- **A-7**: 途中の段から再実行したとき、それより前の段の llm_calls と provider_invocations がどちらも 0 である(fake runner の起動回数で数える)。  
  判定: `pytest -q tests/test_cli.py::test_resume_makes_no_llm_calls_or_invocations_upstream`
