## Acceptance criteria

> 機械可読な写しは `.rein/plan.yaml` のこのタスクの `acceptance:` にあり、ループが読むのはそちら。
> **受入基準1本につきテストのノード ID を1つ割り当ててある**(タスクレビュー AR-1)。

- **A-1**: 台本が Prompt | Pause | Answer | Discrimination のセグメント列として構成され、順序が型と検証で保証される。地の文の「間」が混入する経路が無い。  
  判定: `pytest -q tests/script/test_segments.py::test_segment_order_is_enforced_by_type`
- **A-2**: ラベル列挙判定が 1トラック分のセグメント列を連結した単位で行われ、セグメントを跨いだ4件列挙が赤くなる。英語の冠詞 a や Availability Zone A は落とさない。  
  判定: `pytest -q tests/script/test_label_guard.py::test_cross_segment_enumeration_goes_red`
- **A-3**: 推定再生時間が estimate_seconds(segments, language) で計算され、初期レート(日本語 7.0 文字/秒、英語 2.5 語/秒)が適用される。  
  判定: `pytest -q tests/script/test_duration.py::test_language_specific_rates`
- **A-4**: 3分超過時に「1問分のセグメント列」の境界でのみ分割され、どのパートも Pause を1つ以上含み Prompt で始まる。末尾の Discrimination を切り離す実装と長さで割る実装の両方が赤くなる。  
  判定: `pytest -q tests/script/test_split.py::test_split_only_at_question_boundaries`
- **A-5**: 超過したクラスタが列挙され、打ち切りが起きない。  
  判定: `pytest -q tests/script/test_split.py::test_overlong_clusters_are_listed_not_truncated`
- **A-6**: 仕込んだ矛盾を持つ台本フィクスチャに対し、含意判定が呼ばれて成果物を書かずに非0終了する。  
  判定: `pytest -q tests/script/test_segments.py::test_script_goes_through_entailment`

## Automated-test approach (the basis for the green decision)

- **Test kind**: unit / integration
- **Test file(s)**: `tests/script/test_duration.py`, `tests/script/test_label_guard.py`, `tests/script/test_segments.py`, `tests/script/test_split.py`
- **Test target / cases** — 各ノードについて **何を壊すと赤になるか**:

  - **A-1**: 台本を文字列で持ち正規表現で順序を見る実装 → 地の文の「間」が通るので赤
  - **A-2**: 判定窓をセグメント内に閉じる実装 → セグメント跨ぎ列挙のフィクスチャで赤。英語の冠詞 a を落とす実装も赤
  - **A-3**: 言語を見ない単一レートの実装 → 赤
  - **A-4**: 長さで割る / 末尾の Discrimination を切り離す実装 → どちらも赤
  - **A-5**: 上限超過で打ち切る実装 → 赤
  - **A-6**: script/generate.py が entailment を呼ばない実装 → 赤

> ノード ID は「その名前のテストが存在すること」までしか強制しない — **空の本体(`pass`)でも exit 0 になる**
> ことは実測で確かめてある。上の行は、実装者とレビュアーがその空白を見つけるための唯一の非循環な手掛かりで、
> 最終的な防御はタスク DoD の `review` ステップ(コードレビュアーがテストを読む)。
