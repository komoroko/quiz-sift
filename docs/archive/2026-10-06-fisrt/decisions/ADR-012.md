# ADR-012: R-12 と R-7 の受入基準は artifact 判定にする(node / CosyVoice をゲートに入れない)

- **Status**: accepted
- **Date**: 2026-09-22
- **Decider**: human (finalized at the mandate)
- **Related requirements**: R-7, R-12, NFR-5, NFR-6
- **Supersedes**: この ADR の初版は「CI とイメージに node を入れて E2E を `command` にする」と決めていた。
  敵対的レビュー(AR-2 / AR-3)がその前提を崩したので、結論を差し替えた。

## Background / problem

設計は当初、R-7(生成した音声に無音区間があること)と R-12(ブラウザからテストを実施できること)の
受入基準を、ネットワーク遮断の品質ゲートで `command` として判定するとしていた。
レビューが、その経路が存在しないことを指摘した。

**R-12 側(AR-2)**: 「ブラウザが起動する」の手前に4つ塞がっている。
1. E2E には `npm ci` 済みの `node_modules` と `next build` の成果物が要る。`npm ci` はネットワークを使う。
2. Containerfile が `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` を設定しているので `pytest-playwright` の
   フィクスチャが見つからない。ゲートの argv は凍結されるので `-p` を後から足せない。
3. ランナーは `--user <ホストの uid:gid>` で起動する。`HOME=/home/runner` は uid 1000 の所有なので、
   Playwright の既定のブラウザ探索先が読めない可能性がある。
4. ゲートの中で誰が2プロセスを起動するのかが定義されていない。

**R-7 側(AR-3)**: 実測した事実として、
- `pip download cosyvoice` は**ビルドに失敗する**(git clone + サブモジュール前提の配布)。
  `uv sync --frozen`(ADR-001 の手段)では表現できない。
- torch の CPU wheel だけで 196 MB(圧縮時)。展開と torchaudio と重みを足すとイメージは数 GB 級。
- 重みがイメージに無ければ、ゲート内に mp3 が1つも生まれない。走るのはテスト自身が組み立てた
  合成 PCM に対する `detect_structure` だけで、それは「無音検出器が動くこと」の証拠であって
  「生成した音声に無音区間がある」ことの証拠ではない。

## Options

### Option A: 両方を `artifact` に落とす
- Overview: ゲートでは純粋関数の単体テストと API 契約テストを `command` として走らせ、
  「実際に生成した mp3 に無音がある」「ブラウザから実際に操作できる」はホストで1回実測して記録する。
- Cost: ゼロ。イメージは ffmpeg + 形態素解析辞書 + Python 依存だけで済む。
- Non-functional: **回帰検知が無い**。実装を壊してもゲートは赤くならない。
- Implementation effort: 最小。

### Option B: 両方を `command` にするため、イメージに全部入れる
- Cost: イメージ 5〜8 GB、ビルドは長時間。
- Non-functional: 回帰検知が毎回効く。ただし `command_timeout_sec: 1800` に CosyVoice の CPU 推論と
  Next.js の起動と E2E が全部乗る(AR-22)。`retries: 2` により、超えると 90 分を無駄にしてから赤になる。
- Implementation effort: 大。依存を変えるたびに巨大イメージの再ビルドと再ピン。

## Decision

**Adopted**: Option A(両方 `artifact`)

**Reason**: Option B の実現性が承認前に確かめられる見込みがなく、確かめられないまま凍結すると
最初のタスクがイメージの作り直しから始まる。回帰検知を失う代償は、ADR-006 により
**判定されるロジックが全部 Python 側にある**ことで小さく抑えられている
(UI に残るのは表示と `OptionId` の送信だけ、音声生成に残るのは TTS 呼び出しだけ)。

## Consequences / results

- **サンドボックスイメージから node・Playwright・torch・CosyVoice が消える**。残るのは
  ffmpeg と `uv.lock` から焼いた Python 依存のみ。
- `command` として残るもの: `detect_structure`(合成 PCM に対する無音構造判定)、連番命名の
  ソート順、m3u の形式、API 契約テスト、その他すべての純粋関数。
- `artifact` に降りるもの: **生成した mp3 に無音区間があること**(R-7)、
  **ブラウザからテストを実施・閲覧できること**(R-12)。どちらもホストで1回実測し、
  ログとスクリーンショットを `docs/test/test-plan.md` に記録する。
- D-030(R-3 の再現性測定)、D-048(ゴールデンセット)、NFR-2 の gitignore 等価性(AR-16)と
  あわせて **artifact 判定は計5本**。
- **`/verify` の時点で、artifact 5本の実測が済んでいないと acceptance は通らない**。
- **実行主体**(N-2、人間の判断): **人が事前にホスト環境を用意し、実測コマンドはループが実行する**。
  ループが `rein evidence record` を待つ `external` にはしない — D-003 が external evidence の
  待ちを発生させないと決めているため。セットアップ手順(CosyVoice の導入、`npm ci`、`next build`)は
  `/tasks` で決め、**該当タスクの前提条件として明記する**。
- **What this requires of a person**: **実測が走る前に**、ホストに CosyVoice(git clone +
  サブモジュール + torch + 重み)と `npm ci` 済みの `web/` を用意しておくこと。
  実測コマンドそのものはループが行う。
- **Reversibility**: 可逆。後から `command` へ上げるのは証拠の追加であって、既存の基準を緩めない。
