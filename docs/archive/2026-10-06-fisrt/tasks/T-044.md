## Acceptance criteria

> 機械可読な写しは `.rein/plan.yaml` のこのタスクの `acceptance:` にあり、ループが読むのはそちら。

- **A-1**: 新規インタプリタで判定する。親環境に 13 個の metered 認証変数を入れ、sys.path にスタブの anthropic パッケージを置いた状態で、既定構成のクラスタリング段(cli.main(['cluster', <合成デッキ>]))を1回走らせる。その後、sys.modules に anthropic が無い。positive control として、同じ実行で build_default_llm() が呼ばれ、llm_calls ≥ 1 である。anthropic が import できなければ、skip せず失敗する。claude は PATH に置いた fake 実行ファイル、最小ホームはテストが作った tmp の HOME で満たす。その tmp の最小ホームは T-039 A-4 の実測形(資格情報ファイルを含む)を持つ。後で T-045 が既定の preflight を結線しても、このテストが同じ形のまま緑であるため(AR-140)。  
  判定: `pytest -q tests/nfr8/test_no_metered_sdk.py::test_default_run_never_loads_the_sdk`
- **A-2**: 選択点を SDK アダプタへ差し替えた版では、同じ判定が赤になる。その差し替え版でも llm_calls ≥ 1 は緑である(negative control。import だけで赤になったのではないことを示す)。AnthropicLlm のコンストラクタは (meter) の1引数で、クライアントは本体で構築する。  
  判定: `pytest -q tests/nfr8/test_no_metered_sdk.py::test_swapping_in_the_sdk_adapter_goes_red`
- **A-3**: composition.build_default_llm の本体は return 文1つで、右辺は inspect.isclass で確かめたクラス名の直接呼び出しである。If / Match / Try / Subscript / IfExp / BoolOp / Lambda / Attribute / comprehension / Import を含まない。src/ 全体で、Llm を実装するクラスを構築する式は composition.py の1箇所だけである。  
  判定: `pytest -q tests/nfr8/test_composition.py::test_single_static_selection_point`
- **A-4**: pyproject.toml のコンソールスクリプトはちょうど1つである。それと、__main__ ガードを持つモジュール(python -m の入口)のすべてから到達可能な import グラフに、anthropic など metered API へ HTTP を発行しうるモジュールが 0 件である。cli.py は llm_anthropic を import しない。  
  判定: `pytest -q tests/nfr8/test_entry_points.py::test_no_entry_point_reaches_a_metered_client`
- **A-5**: LlmFactory は Callable[[RunMeter], Llm] になる。外部 LLM 呼び出しに失敗があった実行は、下流へ進まず非 0 で終わり、サマリに未分類比率・最大クラスタ比率・失敗件数が出て、失敗件数は実際の失敗数と一致する。  
  判定: `pytest -q tests/test_cli.py::test_llm_stages_stop_on_failure_and_summarise`
- **A-6**: 各段の inputs_digest に、その段で使うメソッドのモデル ID(ADR-015 の割り当て)が入る。ある段のモデルだけを変えると、その段の digest が変わってキャッシュが無効化される。  
  判定: `pytest -q tests/test_cli.py::test_stage_digest_carries_the_models_it_uses`
- **A-7**: 途中の段から再実行したとき、それより前の段の llm_calls と provider_invocations がどちらも 0 である(fake runner の起動回数で数える)。absorb タスク(T-032〜T-036)の受入テストが緑のまま残る。このタスクが tests/acceptance/ で触れてよいのは conftest.py の実行ヘルパだけで、受入テスト本体は scope の外にある(AR-141)。scope の中にある旧凍結ノード(tests/test_cli.py・tests/safety/test_entailment.py・tests/ports/test_protocols.py)は、呼び出し口の差し替えだけを変え、assert は変えない。  
  判定: `pytest -q tests/test_cli.py::test_resume_makes_no_llm_calls_or_invocations_upstream tests/acceptance/`
