# ADR-009: NFR-1 は uncertain もエラー終了、検証は手書きフィクスチャのみ

- **Status**: accepted
- **Date**: 2026-09-22
- **Decider**: human (finalized at the mandate)
- **Related requirements**: NFR-1

## Background / problem

含意判定器は3値 `consistent | contradicted | uncertain` を返す。`uncertain` の扱いと、
判定器そのものの性能をネットワーク遮断のゲートでどう検証するかを決める必要がある。
スタブでは判定器の性能を測ったことにならない(スタブが「矛盾でない」と返せば誤検出は常に0になる)。

## Options(uncertain の扱い)

### Option A: エラー終了させる
- Non-functional: 誤学習は本人が気づけないので、判定できないものを通すリスクを取らない。
  判定器が曖昧なものを多く返すとパイプラインが進まない。

### Option B: 通すが件数を記録して報告する
- Pros / cons: **「矛盾件数 0」を満たしたまま、確かめていないものが音声になる**。

### Option C: 人にエスカレーション
- Pros / cons: 最も安全だが、100〜200問規模で毎回手作業が発生する。

## Options(検証方法)

### Option D: 録画再生(VCR)+ 実測の併用
- Overview: 合成フィクスチャに対する実 LLM 応答を1回録ってコミットし、ゲートでは再生する。
  録画に `model` と `prompt_digest` を埋め、不一致なら fail。
- Pros / cons: 回帰検知と実性能の両方が取れる。録画の管理コストが乗る。

### Option E: 手書きフィクスチャのみ
- Overview: LLM 応答を人が書いて固定する。
- Pros / cons: **判定器のパースとしきい値ロジックしか測らない**。モデルの判定能力は測っていない。

### Option F: artifact のみ
- Pros / cons: ゲートに証拠が無く、判定器を後から壊しても赤くならない。

## Decision

**Adopted**: Option A(uncertain はエラー終了)+ Option E(手書きフィクスチャのみ)。
ミューテーション検出率に**合格ラインは置かない**(記録のみ)。

**Reason**: uncertain については、誤学習が本人に気づけない種類の失敗であることを優先した。
検証方法については人間が録画の管理コストを取らない判断をした。

## Consequences / results

- `contradicted` と `uncertain` の両方で、**成果物を書かずに**非0終了する(書いてから消す実装にしない)。
- 対象は想起素材・台本・グロッサリ・**クラスタ要約**(AR-21 の処置で追加)。
- **測れるのは判定器のロジックであって、モデルの判定能力ではない**。加えて検出率に合格ラインが無いので、
  **検出率が低くても「矛盾件数 0」は成立する**。この穴は人間が承知のうえで残した。
  誤学習防止は NFR-1 の存在理由なので、次サイクルで実測を入れるかは残る課題として
  `docs/20-design.md` の Open questions に記録した。
- **What this requires of a person**: 手書きフィクスチャ(仕込んだ矛盾・言い換え・ミューテーション)を
  書くこと。ミューテーションの種類と件数を決めること。
- **Reversibility**: 可逆。後から録画再生を足すのは受入基準の追加であって、既存の基準を緩めない。
