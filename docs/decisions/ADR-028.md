# ADR-028: recall・script 段は、項目ごとの途中結果を列の範囲で残し、`--resume` で続きから進める

> script 段の途中結果は ADR-030(D-248)でなくした。script 段は LLM を呼ばない。

- **Status**: proposed
- **Date**: 2026-10-13
- **Decider**: human (finalized at the mandate)
- **Related requirements**: NFR-7、NFR-4、NFR-1、R-4

## Background / problem
段のキャッシュ(`pipeline/stage.StageCache`、T-004)は段単位で、成果物は段がすべての検査を通ったときだけ書かれる。外部呼び出しで止まった段は何も残さない。D-190 の `--resume` は、止まった段を1から走らせ直す。

フル処理の試行3(列 876150982ad5…、2026-10-13)の recall 段は、5時間枠を 21% 使って 27 / 190 問を発行したところで枠切れになった。190 問には枠の約 150% が要るので、新しい枠で再開しても1つの枠に収まらず、何度再開しても完走しない。script 段(全トラックの判定)も同じ形で止まりうる。

## Options

### Option A: 項目ごとの途中結果を、段のキャッシュ鍵に結びつけて残す
- Overview: 段の成果物と同じ場所に、項目ごとの途中結果を置く。場所は `out/<deck>/<stage>/<inputs_digest>.progress/` で、項目1件を1ファイルにする。ファイル名は項目の通し番号にし、本文を名前に使わない。各ファイルは一時パスに書いてから `os.replace` で確定する。
  - recall: 問題ごとに、出力のあった生成の回数と状態を残す。状態は「通過」(想起素材・検査結果・作り直しの回数)、「失格」(上限超過。検査名と回数)、「途中」(使った回数と、判定中の生成物と、その生成物で判定が済んだ主張の判定値)のどれか。
  - script: トラックごとに、判定が済んだ主張の判定値を、返った順に残す。
  - 判定値は主張1件ごとに書く(AR-25)。1回で走った場合、`uncertain` が出てもその項目の不合格は確定しており、`judge` は `contradicted` を探して残りの主張を問い合わせる。判定の途中で枠切れになったとき、既に返った判定値を捨てると、再開で同じ主張を判定器に聞き直すことになる。
  - 再開の手順: 同じ鍵で段を走らせ直すと、通過した項目は呼び出さずにそのまま使い、残りの項目から続ける。recall の「クラスタをまたぐ重複キー」の検査は、通過していた問題を前の問題として数える。
- Cost: 呼び出しは増えない。止まるたびに失うのは、処理中だった1回の呼び出しだけになる。
- Security: 途中結果は教材由来の本文を含む。置き場所は段の成果物と同じ `out/` で、ログにも例外文にも出さない(NFR-2)。
- Non-functional: 鍵(前段成果物・プロンプト・モデル・生成パラメータ・`run_id`)が変われば別の場所になるので、古い途中結果は読まれない。途中結果を使うのは実行の列(`--fresh-run` / `--resume`、鍵に `run_id` が入る)のときだけで、通常モードの実行は途中結果を読みも書きもしない(AR-29。通常モードどうしで失格が残り続けるのを避ける)。
- Implementation effort: StageCache に途中結果の読み書きを足し、2つの段がそれを使う。
- Pros / cons: 枠をまたいで完走できる。段の書き出しまでの経路が増える。

### Option B: 段を細かく分ける(問題の範囲ごとの段)
- Overview: recall を 50 問ずつの段に分ける。
- Pros / cons: クラスタをまたぐ重複の検査が段をまたぐ。段の数が教材の規模で変わる。採らない。

## Decision
**Adopted**: Option A

**Reason**: 人の回答(2026-10-13、D-235)。

## Consequences / results
- 成果物を書く条件は変えない。全項目が検査を通ったときだけ段の成果物を書く(NFR-1)。途中結果は成果物ではなく、下流の段からは読まない。
- **1回で走れば止まる項目は、再開しても止まる**(敵対的レビュー AR-14)。
  - 作り直しの上限は再開をまたいで数える。作り直しの途中で止まった問題は、使った回数の続きから数える。判定の途中で止まった生成物は、残っている主張だけを判定して続ける。
  - recall で失格の問題が途中結果にあれば、作り直さずに `RegenerationExhausted` で止める。
  - script で `contradicted` か `uncertain` の判定値が途中結果にあれば、その主張を判定し直さない。1回で走った場合と同じく、残りの主張を判定したうえで `EntailmentRejected` で止める(`contradicted` が出ていれば残りは問い合わせない)。
  - こうしないと、上限超過や不合格の後に枠切れが来た実行で、再開が上限を実質的に増やし、判定器への聞き直しで NFR-1 を回避できてしまう。
- 呼び出しが失敗した生成(出力が無いもの)は回数に数えない。1回で走った場合も、出力の無い呼び出しは検査されないからである。判定の呼び出しが失敗した主張は判定値を持たず、再開で判定する。
- **再開できるのは、列が枠切れの停止だけで終わった場合に限る**(`run_sequence` の判定は変えない)。TIMEOUT や SCHEMA などで止まった実行があれば、列は従来どおり `not_completable` で、`--resume` は拒否される。
- 途中結果のライフサイクル:
  - 作られる時点: 出力のあった生成と、判定値が返った主張ごと。
  - 消える時点: 段の成果物を確定した時点。
  - 鍵が変わって使われなくなった途中結果と、`not_completable` になった列の途中結果: 前の列の段の成果物と同じ扱いで、`out/` に残る(このサイクルでは掃除しない)。
- cluster 段は対象にしない(D-237)。分類はデッキ全体の1回の処理で、途中で区切れない。試行3では cluster 段が1つの枠に収まった(0.01 → 0.79)。作り直した cluster 段が枠切れで2回続けて止まったら、再開をやめて `/revise` に戻る。
- glossary 段は対象にしない。このサイクルのフル処理に含めない(D-234)。
- ログに残すのは、再開で使った項目の件数と残りの件数だけにする(NFR-2)。
