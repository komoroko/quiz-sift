# ADR-005: 学習記録ストアは SQLite

- **Status**: accepted
- **Date**: 2026-09-22
- **Decider**: human (finalized at the mandate)
- **Related requirements**: R-8, R-10, R-11, R-12

## Background / problem

D-023 が「学習記録はサーバ側に置き、CLI と UI の双方が読み書きする」と決めている。実体を選ぶ。

## Options

### Option A: SQLite(`sqlite3`、stdlib)
- Cost: ゼロ。
- Non-functional: 集計クエリが楽。CLI と server の同時アクセスに WAL モードが要る。
  スキーマ変更に移行が要る。
- Implementation effort: 中。

### Option B: JSON Lines 追記
- Non-functional: **破壊的更新が構造的に無いので可逆性が最も高い**。集計は全読み込み。
  同時書き込みにファイルロックが要る。
- Implementation effort: 小。

### Option C: JSON ファイル(全体を読み書き)
- Pros / cons: **CLI と UI の双方が書くので並行書き込みで壊れる**。

## Decision

**Adopted**: Option A(SQLite)

**Reason**: stdlib で依存が増えず、R-8 のレポート・R-10 の誤答率集計・R-11 のデッキ別分離が
いずれもクエリで書ける。並行アクセスは WAL で扱える。

## Consequences / results

- `store/location.py` が**パス決定関数とスキーマ定義を1箇所で持つ**(R-12 の受入基準の実体)。
  所在をハードコードする第2の経路を作らない。
- WAL モードを有効にする。
- **スキーマ移行は不可逆**: 本人の学習記録が壊れると再現できない。本サイクルは記録が空から始まるので
  実害は小さいが、**次サイクル以降のスキーマ移行タスクは `reversible: false` になる**。
- **What this requires of a person**: なし(DB ファイルは自動生成)。
- **Reversibility**: 本サイクル内では可逆(DB ファイルの削除で戻る)。次サイクル以降は上記のとおり。
