## Acceptance criteria

  判定: `pytest -q tests/adapters/test_llm_claude_cli.py::test_argv_matches_the_frozen_shape_and_the_fixture`
- **A-2**: ClaudeCliLlm.__init__ の本体が属性代入と引数なしのクラス呼び出しだけで、if / match / try / 添字 / os.environ / ファイル読み出し / importlib を含まず、キーワード既定値を持たない(AST で判定)。  
  判定: `pytest -q tests/adapters/test_llm_claude_cli.py::test_init_body_is_assignments_and_bare_class_calls`

  判定: `pytest -q tests/adapters/test_llm_claude_cli.py::test_a_call_creates_nothing_under_home`
- **A-4**: usage は成否の判定より先に meter へ渡り、PARSE / SCHEMA / TRUNCATED / INCOMPLETE_IDS / PROVIDER_ERROR のどれで終わった呼び出しでもトークンが記録される。1回の classify_clusters が 25 問ごとに分割されて provider_invocations を増やし、llm_calls は 1 だけ増える。失敗があれば ClassificationResult.failures に入り、その reason は FailureKind の値で始まる。再試行しない。

## Notes / design decisions

- `Workspace` はゲートでも差し替えない(AR-72)。`tmp_path` を根にして実物を走らせ、最小ホームの形(資格情報1ファイル)は
  テストが自分で作る。
- ファクトリは T-028 の `tests/nfr8/` が PATH に置く fake `claude` の出力源にもなる(AR-99。T-028 も `tests/support/` を scope に持つ)。
- 設計のモジュール表は `llm_claude_cli.py` の役割に「待機」を書いていたが、D-091 撤回で待機は無い(設計を直した)。
- `apiKeySource` の毎回の検証は課さない(NFR-8 の「この基準が測っていないこと」)。
- **fake の差し方**: `__init__` は引数を取らないので、テストは `ClaudeCliLlm(meter)` を構築した後に runner 属性を fake へ置き換える(設計の「テストコードからの直接構築で注入」の具体形)。構築に副作用が無い(D-115)ので、サンドボックスでも構築は通る。
- レート枠は `rate_limit_event` を読んだこのアダプタが `record_quota` で渡す(D-114)。

- **tasks 段レビュー(AR-109 / AR-110)**: 実物フィクスチャは meta の exit_code と stderr を付けて判定器へ渡す。骨格判定は result を持つ全形に及び、A-5 の4キーは値の置き換えだけ(キーは消さない)。
