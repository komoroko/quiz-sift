## Notes / design decisions

- absorb タスク(D-121、D-147)。旧サイクルで実装し、acceptance に届かなかった部分を、claim の文面の粒度で受入テストに固定する。製品コードは変えない。テストが赤になったら、それは既存実装の欠陥である。黙って直さず、needs-revision で止める(ゲート規則3)。テストは tests/acceptance/ に置く。合成フィクスチャと既存のスタブだけを使い、実教材は使わない(NFR-2)。cli.main を通すテストは、T-032 が置く tests/acceptance/conftest.py の実行ヘルパ(llm / tts の差し替えを1箇所に集めたもの)だけを使う。後続の T-044 と T-045 が LlmFactory の型と preflight 引数を変えるとき、直すのはこの conftest.py だけで、受入テスト本体(test_*.py)は両タスクの scope の外にあるので書き換えられない(AR-141)。受入テストは、このヘルパと既存の合成フィクスチャ以外に、ほかのテストパッケージの conftest を import しない(AR-151)。呼び出し回数は stub の呼び出し回数か、Pipeline / Meter の戻り値で数える。out/<deck>/meter.jsonl の行数や行の形は読まない(T-037 と T-045 が行形式を変えるため。AR-156)。変更はテストだけなので、negative control は取れない。「制御されていない緑」として記録される。
