# ADR-021: 学習記録ストア v2 と旧形式の拒否(ADR-005 を改める)

- **Status**: proposed
- **Date**: 2026-10-06
- **Decider**: human (finalized at the mandate)
- **Related requirements**: R-8、R-12

## Background / problem

学習記録は `attempts.chosen_option_id`(単一)を持つ。複数正解問題では選んだ集合を記録し、完全一致だけを正答にする(D-173)。既存の記録に残すものは無い(D-175)。

## Options

### Option A: 作り直し、旧形式はエラーで止める(採用)
- Overview: `chosen_option_ids TEXT NOT NULL`(整列した JSON 配列)、`PRAGMA user_version = 2`。所在は変えない。テーブルがあって版が 2 でなければ `LegacyStoreError` で止まる。
- Cost: 小。
- Security: 影響なし。
- Non-functional: 1行1回答のまま。SQL から集合を問い合わせる用途は無い。
- Pros / cons: 移行コードが無い。旧ストアを持つ人は退避が要る。

### Option B: 移行を書く
- Pros / cons: 残す記録が無いので不要(D-175)。後方互換を持たない方針にも反する。

## Decision
**Adopted**: Option A

**Reason**: D-175(残す記録なし)と、黙って読み替えない要件(R-8)。所在を変えないのは、変えると旧形式の検出が発火しないため(D-203)。

細目(loop が決めた local の事項):
- 保存の形は JSON 配列の列(子テーブルにしない)。
- 旧形式の判定は `user_version` を主とし、テーブルがあって版が 0 のものも旧形式とみなす(fail closed)。
- 製品は旧ストアを消さない。エラーメッセージで所在と版を示し、別名への退避を案内する(D-204)。
- API は `chosen: list[str]` だけを受け、型違い・重複・N 件以外・未知 ID を 400 で拒否する。`present` は `select_count` を返す。

## Consequences / results
- UI は `select_count > 1` で複数選択に切り替わり、ちょうど N 件のときだけ送信できる。

### What this requires of a person
- 旧ストア(`out/learning.sqlite3`)がある場合、エラーを見たら別名へ退避すること。

### Reversibility
- 退避(rename)は可逆。製品は削除しない。
- スキーマの変更はコミットを戻せば元に戻るが、v2 で書いた記録は旧コードでは読めない。
