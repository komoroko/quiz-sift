# ADR-007: Udemy 抽出は既存ブラウザへ CDP 接続

- **Status**: accepted
- **Date**: 2026-09-22
- **Decider**: human (finalized at the mandate)
- **Related requirements**: R-2, NFR-3

## Background / problem

Udemy の有料問題集はログインの背後にある。抽出方式によって、**プログラムが認証情報を持つかどうか**と
**R-2 の不可逆性の大きさ**が変わる。不可逆性は承認ゲートの数に直結する。

## Options

### Option A: Playwright で自動ログイン
- Security: パスワードまたは `storage_state` をプログラムが持つ。**NFR-3 の対象が増える**。
- Non-functional: 待機とセレクタが堅牢。ボット検知のリスクは残る。

### Option B: 既存ブラウザへ CDP 接続
- Overview: 人がログイン済みの Chrome をデバッグポート付きで起動し、そこへ接続する。
- Security: **パスワードをプログラムが一切持たない**。セッションはブラウザ側にある。
- Non-functional: ボット検知を回避しやすい。毎回ブラウザを起動する手間がある。

### Option C: 手動 DOM ダンプ
- Security: 認証情報を一切扱わない。**R-2 の不可逆性がほぼ消え、承認ゲートが1つ減る**。
- Pros / cons: 手間が問題数に比例し、R-2 の「自動抽出」という要件の中身が薄くなる。

## Decision

**Adopted**: Option B(既存ブラウザへ CDP 接続)

**Reason**: 認証情報の取り扱いを消しつつ、抽出の自動化は保つ。NFR-3 の対象面が最小になる。

## Consequences / results

- **抽出器は「HTML 文字列 → 結果」の純粋関数にする**。ブラウザは HTML を取ってくるだけ。
  これで合成 HTML フィクスチャに対するテストがサンドボックスで走る(ブラウザ不要)。
- **NFR-3 の対象から Udemy の認証情報が消える**。残るのは Anthropic API キーのみ。
- **依然として不可逆な面が残る**: Udemy へのページ取得はアカウントにアクセス履歴を残し、
  アクセスパターンによってはボット検知を招く。これは戻せない。
  **→ `/tasks` では「抽出ロジック(可逆)」と「実取得の実行(不可逆)」を別タスクに分け、
  後者を `reversible: false` として承認ゲートにする。**
- **What this requires of a person**:
  (1) ログイン済みの Chrome をデバッグポート付きで起動しておくこと(毎回)。
  (2) 対象 URL。
  (3) 二要素認証・ボット検知に遭遇した場合の手動介入。
  (4) 規約解釈の責任(D-007)。
- **Reversibility**: コードは可逆。実取得の実行は上記のとおり不可逆。
