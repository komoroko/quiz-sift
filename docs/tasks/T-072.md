## To do
- `adapters/llm_claude_cli.py` の子プロセスを起動する1か所(`_invoke` の周り)で、判定が `TRUNCATED` の子だけを同じ argv と stdin で最大 `MAX_REISSUES`(= 2)回出し直す。`_call` と `classify_clusters` のバッチの両方がそこを通るようにする。
- 出し直した子も `begin_invocation` から `end_invocation`・`record_failure`・`log_invocation` まで通常の1本として記録する。`begin_call`(`llm_calls`)は増やさない。
- 他の失敗の種別(`PROVIDER_ERROR`、`SCHEMA`、`PARSE`、`TIMEOUT`、`INCOMPLETE_IDS`、`SPAWN`)は出し直さない(D-101)。

## Acceptance criteria
> 機械が読む写しは `.rein/plan.yaml` のこのタスクの `acceptance:`。

- **A-1**: 子プロセスが TRUNCATED で終わった呼び出しは、同じ argv と stdin で最大 MAX_REISSUES(= 2)回まで出し直し、成功すればその値を返す。出し直しも子プロセス1本として meter に入り(provider_invocations に数え、llm_calls には数えない)、1回の Protocol 呼び出しの中で完結する。  
  判定: command — `pytest -q tests/adapters/test_llm_claude_cli.py::test_truncated_invocation_is_reissued_up_to_the_limit`
- **A-2**: 出し直しは TRUNCATED だけが対象で、PROVIDER_ERROR(枠切れ・overage を含む)・SCHEMA・PARSE・TIMEOUT・INCOMPLETE_IDS は1本目で失敗のまま返る。1 + MAX_REISSUES 本すべてが TRUNCATED なら TRUNCATED の ContractError になる。  
  判定: command — `pytest -q tests/adapters/test_llm_claude_cli.py::test_only_truncated_is_reissued`
- **A-3**: classify_clusters のバッチの呼び出しも同じ規則で出し直す(子プロセスを起動する経路はすべて同じ1か所を通る)。  
  判定: command — `pytest -q tests/adapters/test_llm_claude_cli.py::test_classify_batches_reissue_truncated_invocations`

## Notes / design decisions
- 背景(D-231): フル処理の試行1で、recall の 206 本中 2 本が error_max_turns で落ちた。子のセッション記録の構造(件数だけ)では、StructuredOutput への入力が「JSON として読めない」と3ターンとも拒否されていた。1回だけ拒否されて2ターン目で通った子は 15 本ある。モデル側の確率的な失敗なので、同じ入力で出し直せば通る見込みが高い。
- `--max-turns` は上げない。argv のダイジェストが変わり、`pipeline/overhead.OVERHEAD` の定数(T-046 の実測)が unknown になるため。
- 出し直しは「何を・なぜ・どの範囲で」をログに残す(問題 ID と回数だけ。教材本文は載せない、NFR-2)。
