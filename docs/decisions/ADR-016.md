# ADR-016: TRUNCATED の証拠を実物フィクスチャから fake に切り替える

- **Status**: accepted
- **Date**: 2026-09-25
- **Decider**: human (finalized at the mandate)
- **Related requirements**: R-3, NFR-6

## Background / problem

ADR-013 と設計 NFR-6 節は、実 CLI から採取する契約フィクスチャを3件と決めていた。
成功 / `--max-turns 1` による `error_max_turns`(`TRUNCATED`)/ 不正な `--json-schema` による `PARSE` の3件である。
T-029 のホスト実測(2026-09-25、claude 2.1.282)で、このうち2つの前提が崩れた。

1. `--max-turns 1` が `error_max_turns` にならない。haiku でも `claude-opus-5-5` でも、`stream-json` でも `json` でも、
   結果は `subtype: success` / `num_turns: 2` / `terminal_reason: completed` だった。
   StructuredOutput で完了する呼び出しは、ターン上限に掛からないらしい。
   要件作成時には `error_max_turns` を観測していたが、2.1.282 では再現しない。
2. 不正な `--json-schema` の `Error: ...` は、標準出力ではなく標準エラーに出る。標準出力は空で、終了コードは 1。
   これは D-119(local)で扱う。期待する種別は `PARSE` のまま変わらない。

1 は、R-3 の `TRUNCATED` 分岐を何で証拠立てるかという問題である。受入基準が要求する証拠の種類が変わるので、人間が決めた。

## Options

### Option A: 実物を外して fake で検証する(採用)
- Overview: 実物フィクスチャは成功と `PARSE` の2件にする。`TRUNCATED` の判定枝は残し、単一ファクトリの fake で検証する。
  fake の骨格は成功フィクスチャから作り、`subtype` / `is_error` / `stop_reason` / `structured_output` だけを差し替える。
- Cost: 追加の実呼び出しは無い。
- Security: 変化なし。
- Non-functional: 実物の `error_max_turns` の形は `unknown` のまま残る。
  実物が別の形で来た場合は `PROVIDER_ERROR` に数えられる。失敗に倒れて非 0 終了するので下流は壊れないが、失敗の内訳が1種ずれる。
- Implementation effort: T-029 / T-026 / T-027 の受入基準の文面を直すだけ。
- Pros / cons: 確実に完了する。一方で、`TRUNCATED` の分岐は実装者自身の fake に対してしか検証されない。

### Option B: 別の再現手段を T-029 で探す
- Overview: ツールを禁止するプロンプトや `--max-turns 0` などを試す。
- Cost: 実呼び出しが数回から十数回かかる。
- Pros / cons: 採れれば証拠は強い。採れなければ T-029 は再び needs-revision で止まる。確実性は低い。

### Option C: `error_max_turns` の分岐を削る
- Overview: `TRUNCATED` を `stop_reason` だけで識別する。
- Pros / cons: 検証できない分岐が消える。ただし R-3 の本文を変える必要があり、CLI の版で挙動が戻ったときは `PROVIDER_ERROR` に落ちる。

## Decision
**Adopted**: Option A

**Reason**: 採取手段が無いことは実測で確かめた。判定枝は残すので、CLI の版で挙動が戻っても正しく数えられる。
実物の形は T-020 の実測で `TRUNCATED` か `PROVIDER_ERROR` が出たときに採り、次サイクルのフィクスチャにする。

## Consequences / results
- T-029 A-1 の実物フィクスチャは2件になる。`error_max_turns` の採取物は success だったので、フィクスチャから外す。
- T-027 A-5 は、実物の2件と、ファクトリが作る `error_max_turns` 形の fake を別々に判定する。
- `docs/20-design.md` の Open questions に「`TRUNCATED` の実物の形は未観測」を置く。
- 要件 NFR-8 (g) の「`--max-turns` は 3 以上」は変えない。根拠文だけを実測に合わせる。

### What this requires of a person
- 何も要らない。T-020 の実測ログで `TRUNCATED` か `PROVIDER_ERROR` が出た場合に、その形を次サイクルで確かめる。

### Reversibility
- 可逆。コミットを戻せば元に戻る。実物が採れるようになれば、フィクスチャを1件足して fake の検証と並べればよい。
