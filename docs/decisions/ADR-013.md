# ADR-013: 既定の LLM 呼び出し経路は Claude Code CLI(サブスクリプション認証)

- **Status**: accepted(**supersedes ADR-002 の「プロバイダは Anthropic SDK、モデルは claude-opus-5」の部分**)
- **Date**: 2026-09-25
- **Decider**: human (finalized at the mandate)
- **Related requirements**: NFR-8, NFR-7, NFR-2, NFR-6, R-3, R-4, R-5, R-6, NFR-1

## Background / problem

リポジトリの持ち主が「**LLM の利用は従量課金(metered API billing)を伴ってはならない**」という制約を
新たに課した(D-084)。ADR-002 が決めた Anthropic SDK + `ANTHROPIC_API_KEY` の直接呼び出しは、
この制約と両立しない。`/revise --to mandate` で mandate を差し戻したうえで経路を選び直す。

`ports/llm.py` の `Llm` Protocol・`TokenUsage` の4値・`UsageRecorder` は**変えない**。ADR-002 の
Option B(1社 + タスク別メソッド)という判断はそのまま生きている。**ただし「動くのは呼び出し経路
だけ」ではない**(AR-70): 計測の Protocol(`RunMeter`)は新設され、分類プロンプトとスキーマは
ID 完全性のために中身が変わり(全ステージのキャッシュが1回無効化される)、失敗分類は形ごと
作り直しになる。波及の実体は Consequences に書いたとおり。

## Options

### Option A: Claude Code CLI(`claude -p`、サブスクリプション認証)
- Overview: `ports/llm.py` の実装を、`claude` を子プロセスとして起動するアダプタに差し替える。
- Cost: **従量課金ゼロ**。代わりにサブスクリプションのレート枠を消費する。
- Non-functional: 実測(2026-09-24〜25、CLI 2.1.281)で次を確認した。
  - `--json-schema` でスキーマ強制が効き、フェンス無しの適合 JSON が返る(ADR-002 の
    `output_config.format` と等価)。
  - `usage` が `input_tokens` / `cache_creation_input_tokens` / `cache_read_input_tokens` /
    `output_tokens` / `output_tokens_details.thinking_tokens` を返す(AR-29 の4値要求を満たす)。
  - `total_cost_usd` が返る(**notional 値**。実課金は発生しない)。
  - `--output-format stream-json` の `init` イベントが `tools` と `apiKeySource` を返し、
    `rate_limit_event` がレート枠の使用率とリセット時刻を返す。
  - API キーが一切不要になる(NFR-3 に対して厳密に改善)。
- 弱点: 呼び出し1回あたり製品外のオーバーヘッドが Opus 5 で 14,603 tok、Haiku 4.5 で 8,506 tok
  乗る。教材本文が `~/.claude/projects/**/*.jsonl` に平文で残る(D-086 が許容)。CLI は
  ホストに置かれ自動更新されるので、ADR-001 の「依存をイメージに焼く」が効かない。
- Implementation effort: **大**(AR-70 により改訂。当初「中」と書いたが実物と合わない)。新規モジュール9本、
  新しい Protocol(`RunMeter`)と `LlmFactory` の型変更、分類プロンプトとスキーマの書き換え、
  失敗分類6種とレート制限の待機、単価表の2モデル化、オーバーヘッド定数の測定手順、契約フィクスチャ3件。
  却下した Option C の工数を「1サイクル」と書いた以上、採用案も同じ尺度で書く。

### Option B: Anthropic SDK のまま(現状維持)
- **却下**: NFR-8 違反。制約そのものを満たせない。

### Option C: ローカル OSS LLM
- Overview: ホストの GPU(RTX 5070 Ti / 16 GB)で開放重みモデルを動かす。
- Pros: 従量課金もレート枠も無く、教材本文がホスト外へ出ない(D-086 の平文コピーも不要)。
  構造化出力は guided decoding で SDK 以上に固い。
- Cons: 16 GB は CosyVoice(ADR-004)と共有で、日本語の含意判定(NFR-1)と分類(R-3)の品質が
  未知。ADR-012 が node と重いランタイムをイメージから外した判断とも衝突する。品質の実測に
  1サイクル要る。
- **却下**: 本サイクルは測定器の完成が acceptance(D-003)であり、LLM の品質を測り直す余地がない。
  次サイクルの選択肢としては生きている。

### Option D: Claude Agent SDK(Python)経由
- Pros: 型が付き、パースを自分で書かなくてよい。
- **却下**: サブプロセス境界が SDK の内部に隠れ、**NFR-8 (b)(e) の観測点(argv・env・cwd)が消える**。
  判定できない基準は基準ではない。

## Decision

**Adopted**: Option A。`adapters/llm_claude_cli.py` を既定とし、`adapters/llm_anthropic.py` は
コードに残して既定から外す(D-090)。出力形式は `stream-json`、`--max-turns` は 3 以上。

**Reason**: 制約(従量課金の禁止)を満たす唯一の現実的な経路であり、実測で ADR-002 が依拠していた
2つの性質 — スキーマ強制と4値トークンの内訳 — がどちらも保たれることを確認できた。ADR-002 の
判断のうち動かす必要があるのは経路だけで、Protocol もプロンプトの置き場も変えずに済む。

## Consequences / results

- `anthropic` は通常依存から **optional extra** へ移る(D-090)。`uv.lock` →
  `.rein/oci/quiz-sift/requirements.txt` → サンドボックスイメージのダイジェスト →
  `config.yaml` の再ピンまで波及する(ADR-001)。**mandate 承認前に済ませる必要がある。**
- `pyproject.toml` に `[project.scripts]` を**1本だけ**追加する(NFR-8 (d) が
  「コンソールスクリプトが1つだけ」を機械判定するため。現在は 0 本)。
- `src/quiz_sift/cli.py` の `from quiz_sift.adapters import llm_anthropic` を**削除する**。
  現状これがあるため、CLI を import しただけで `sys.modules` に `anthropic` が入り
  **NFR-8 (a) が確定的に赤になる**。プロンプトとスキーマの定数を SDK に触らない
  `adapters/llm_prompts.py` へ移し、`inputs_digest` はそちらを読む。
- NFR-7 の単価表は **2モデル分**になる(ADR-015 の混成)。`priced_at` に加えて**取得元**を持つ。
- **What this requires of a person**: (1) ホストに `claude` が在りログイン済みであること、
  (2) ADR-014 の最小ホームを1回セットアップすること、(3) サンドボックスイメージの再ビルドと
  ダイジェストの再ピン。
- **Reversibility**: **可逆**。`composition.build_default_llm()` の1行と `pyproject.toml` の
  revert で戻る。ただしモデル ID とプロンプトが `inputs_digest` に入るので、**切り替えは全 LLM
  ステージの再実行を意味する**(金額はゼロだが、レート枠と時間を丸ごと1回分使う)。
