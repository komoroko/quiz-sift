## Acceptance criteria

> 機械可読な写しは `.rein/plan.yaml` のこのタスクの `acceptance:` にあり、ループが読むのはそちら。
> **受入基準1本につきテストのノード ID を1つ割り当ててある**(タスクレビュー AR-1)。

- **A-1**: 抽出器が「HTML 文字列 -> 結果」の純粋関数で、ブラウザ無しに合成 HTML フィクスチャに対して動く。  
  判定: `pytest -q tests/extract/test_udemy.py::test_extractor_is_a_pure_function_of_html`
- **A-2**: selector_kind が実行時にマッチした規則から導出され、フォールバック枝ごとに別の値を返す。DOM 構造が問題ごとに異なる negative control フィクスチャに対して集合サイズが 2 になり、種別一致の判定が赤くなる。  
  判定: `pytest -q tests/extract/test_evidence.py::test_selector_kind_negative_control_goes_red`
- **A-3**: 抽出失敗が ExtractionFailure、取得失敗が FetchFailure として別々に列挙され、両方が報告件数に算入される。空文字で埋める経路が型で塞がれている。  
  判定: `pytest -q tests/extract/test_failures.py::test_element_and_fetch_failures_are_separate`
- **A-4**: 書き出し先が .gitignore 対象であることを起動時に検証してから開く。  
  判定: `pytest -q tests/extract/test_writer.py::test_writer_validates_gitignore_before_opening`
- **A-5**: 公式解説を取得できた問題数とできなかった問題数が ExtractReport に出る。  
  判定: `pytest -q tests/extract/test_udemy.py::test_explanation_fetch_counts_are_reported`
- **A-6**: 書き出した JSONL が ingest のバリデータを通り、壊れた1行があれば非0終了する。  
  判定: `pytest -q tests/extract/test_writer.py::test_output_passes_ingest_validator`

## Automated-test approach (the basis for the green decision)

- **Test kind**: unit / integration
- **Test file(s)**: `tests/extract/test_evidence.py`, `tests/extract/test_failures.py`, `tests/extract/test_udemy.py`, `tests/extract/test_writer.py`
- **Test target / cases** — 各ノードについて **何を壊すと赤になるか**:

  - **A-1**: 抽出器がブラウザ接続を内部で張る実装(HTML 文字列だけで呼べない)→ 赤
  - **A-2**: selector_kind を定数にする / 1つの汎用規則で両 DOM 形状を吸収する実装 → negative control で集合サイズ 1 のまま赤
  - **A-3**: 取得失敗を要素失敗に混ぜる / 空文字で穴埋めする実装 → 赤
  - **A-4**: 検証せずにファイルを開く実装 → 赤
  - **A-5**: 解説の取得可否を数えない実装 → 赤
  - **A-6**: 壊れた JSONL を書いて 0 で終わる実装 → 赤
