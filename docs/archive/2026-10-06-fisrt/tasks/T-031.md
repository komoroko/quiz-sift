## To do

`ports/metering.py` に `RunMeter` Protocol・`FailureKind`(7種、D-104)・`RateLimitInfo`・`InvocationScope` を置き、
`pipeline/meter.py` の `Meter` をそれに合わせて作り直す。設計 NFR-7 節の「ログのフィールド一覧」が出力の正で、
キー名はそこから写す。**`estimated_cost` は改名しない**(D-113)。T-002 の A-2 / A-3 のテストノードは緑のまま残す。

- `begin_call(method)` → `llm_calls += 1`。`begin_invocation(argv_digest)` → `provider_invocations += 1`(D-107)。
  `end_invocation(model, turns, usage, cost_usd)` → `model_turns` / `turns_by_model` / `tokens_by_model` を積む。
  `turns` / `usage` が `None` の呼び出しは別に数える。`record_quota(info)` は最初の値を start、最後の値を end にする(D-114)。
- `ended_by_rate_limit` は D-110 の規則で決める。実行ログに `material` は置かない(D-116)。
- 単価表は `claude-opus-5-5` と `claude-haiku-4-5` の2モデル。**取得元 URL は Anthropic の料金ページ**
  (`https://platform.claude.com/docs/en/about-claude/pricing`)から実装時に読んで写し、`priced_at` をその日にする。
  キャッシュ書き込み・読み出しの倍率も同じページから取る。
- 単価表に無いモデル ID は例外にせず `{"status":"unavailable","reason":"unknown_model"}`。単価が1つでも 0 なら
  `zero_price`。
- `pipeline/overhead.py` に `OverheadConstant(model, per_turn_tokens, bucket, measured_at, cli_version, argv_digest)`
  の型と**空の**モデル別表を置く。値は T-030 が実測して埋める。定数が無いモデルの overhead は `unknown`。
- `max_concurrency` は定数 1(D-100)。待機時間の欄は置かない(D-091 撤回)。

scope: `src/quiz_sift/ports/metering.py`, `src/quiz_sift/ports/__init__.py`, `src/quiz_sift/pipeline/meter.py`, `src/quiz_sift/pipeline/overhead.py`, `tests/ports/test_metering.py`, `tests/pipeline/test_meter.py`

  判定: `pytest -q tests/ports/test_metering.py::test_run_meter_protocol_and_failure_kinds`
- **A-2**: Meter.finish が書く JSON Lines の1行に、設計 NFR-7 節のフィールド一覧の全キー(run_id から quota_at_end まで)が現れ、llm_calls・provider_invocations・model_turns・turns_by_model が begin_call / begin_invocation / end_invocation の回数と num_turns の総和に一致する。quota_at_start / quota_at_end は record_quota が最初と最後に受けた値である。キーを1つでも欠く行は赤。T-002 の A-2 / A-3 のテストノード(test_meter_records_run_fields / test_token_breakdown_and_price_provenance)は緑のまま残る(D-113)。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_meter_line_carries_every_nfr7_field`
- **A-3**: 既知のトークンベクタと既知の単価表に対する estimated_cost.computed が手計算の期待値に一致し、declared(end_invocation に渡った cost_usd の総和)と relative_diff が記録される。単価が1つでも 0 なら status が unavailable / zero_price になり、単価表に無いモデル ID では例外を投げず unavailable / unknown_model になる。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_notional_cost_computed_declared_and_unavailable`
- **A-4**: 既定の単価表が claude-opus-5-5 と claude-haiku-4-5 の2モデルを持ち、4値の単価がすべて 0 より大きく、各モデルが priced_at と取得元 URL(空でない)を持つ。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_price_table_has_two_models_with_sources`
- **A-5**: usage が None で終わった呼び出しは invocations_without_usage に、turns が None の呼び出しは invocations_without_turns に数えられ、失敗した呼び出しの usage もトークン総量に加算される。failures_by_kind は7種すべてのキーを持つ。ended_by_rate_limit は D-110 の規則(実行を止めた失敗が PROVIDER_ERROR で、その呼び出しの最後の rate_limit_info の status が allowed_warning 以外)で真になり、真のとき resetsAt を併記する。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_failed_and_usage_less_invocations_are_counted`
- **A-6**: overhead がモデル別の写像として出力され、記録された argv_digest が begin_invocation に渡された argv のダイジェストと違う、または定数が無いモデルは unknown と報告される。テストは定数表を注入して判定し、pipeline/overhead.py の既定の表に依存しない(T-030 が表を埋めても赤にならない)。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_overhead_is_unknown_on_argv_mismatch_and_quota_is_recorded`
- **A-7**: estimated_cost に "notional": true が入り、同じ行に免責の1行が含まれ、キーにも値にも billed / charged / 実課金 の語が現れない。語を1つ差し込んだ出力に対して判定が赤になる。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_output_is_notional_and_never_claims_billing`
