# ADR-017: 最小ホームを中身で検査し、子プロセスに --safe-mode を課す

- **Status**: accepted
- **Date**: 2026-09-26
- **Decider**: human (finalized at the mandate)
- **Related requirements**: NFR-8 (b)(e)
- **Decisions**: D-122, D-130, D-133

## Background / problem

ADR-014 は最小ホームを「人間が事前に用意し、製品は `.claude/.credentials.json` の存在だけを確かめる」と決めた。
2026-09-25 の実測で、この前提が2点で崩れた。

1. CLI 自身がログインと同期で `settings.json`(`{"theme"}` だけ)・`skills/synced`・`plugins/synced` を最小ホームに書く。
   そのため、旧 T-024 の「`settings.json` があれば拒否する」判定では、最小ホームが必ず拒否される。
2. 番兵を置いた実測では、設計の argv が次の4箇所を読んでいた([claude-cli-home-probe.md](../test/measurements/claude-cli-home-probe.md) §1)。
   - `~/.claude/CLAUDE.md`
   - `~/.claude/rules/*.md`
   - 作業ディレクトリの祖先にあたる、誰でも書ける `/tmp/CLAUDE.md` と `/tmp/.claude/CLAUDE.md`

   これは、ツールを `StructuredOutput` 1本に絞っても残る指示注入の経路である。

## Options

### 読み込みの遮断(D-130)

#### Option A: `--safe-mode` を argv に必須で足す
- 概要: 実測では4箇所とも読まれず、`memory_paths` は null になった。OAuth は使え(`apiKeySource: none`)、`init.tools` は `["StructuredOutput"]` のままだった。
- セキュリティ: CLAUDE.md 系の経路を CLI 側で閉じる。ただし次の2つは閉じない。
  - `settings.json` の `env` は `--safe-mode` の下でも効く(probe §2)。
  - 管理設定(`/etc/claude-code/`)は塞げない。
- 非機能: argv が変わるので、`argv_digest` とオーバーヘッド定数、契約フィクスチャを取り直す必要がある(D-133)。
- 工数: 小。

#### Option B: `--bare`
- 却下: OAuth を読まず、サブスクリプション認証が使えない(実測)。

#### Option C: 製品側の検査だけで塞ぐ
- 却下: 作業ディレクトリの祖先(`/tmp`)は誰でも書け、実行ごとに状態が変わる。検査の時点と読み込みの時点の間に競合(TOCTOU)が残る。

### 最小ホームの検査(D-122)

#### Option A: 有無で判定する(旧 T-024)
- 却下: CLI 自身が書く `settings.json` で、必ず拒否になる。

#### Option B: 中身で判定する
- 拒否する条件:
  - `.claude/CLAUDE.md` がある。
  - `.claude/rules/` の配下にファイルがある。
  - `.claude/settings.json` のトップレベルのキーが `{theme}` の部分集合でない。JSON として読めない場合、トップレベルが object でない場合も拒否する。
- 同期物(skills・plugins)は拒否しない。
- `.credentials.json` は存在だけを確かめ、開かない。

## Decision

**Adopted**: 読み込みの遮断は Option A、最小ホームの検査は Option B。両方を課す。

**Reason**:
- `--safe-mode` は CLAUDE.md 系の読み込みを CLI の側で止める。これが主な守りになる。
- ただし `settings.json` の `env` は `--safe-mode` でも効く。`ANTHROPIC_BASE_URL` を向け替えると、呼び出しは実際に向け替わった先へ行った(probe §2)。そのため、中身の検査は二重の守りではなく、`env` についての唯一の守りになる。
- 検査対象の CLAUDE.md 系の場所は、実測で読まれた場所に絞った。

## Consequences / results

- ADR-014 の「存在だけを確かめる」は、この ADR の中身検査で置き換わる。検査は `Workspace` の起動前検査が行う。
  - 検査は読むだけで、何も書かない。
  - 検査に落ちた起動は、実行の列に登録されない(ADR-018、D-132)。
- 契約フィクスチャ(success / invalid_schema)を、`--safe-mode` 付きの argv で取り直す(D-133)。
  - 取り直しは実 CLI の呼び出しなので、レート枠を消費する。
  - `claude-opus-5-5` と `--safe-mode` の組み合わせは、まだ実測していない。
- 番兵による「読み込み 0 件」はホスト実測の `artifact` 証拠とし、採取経路をリポジトリに置く。
  - positive control として、`--safe-mode` を外すと読まれることを同じ採取で示す。
  - 番兵は元のバイト列の sha256 で後始末を確かめる。

### What this requires of a person

- 最小ホームの `.claude/settings.json` のキーを `{theme}` に保つこと。`.claude/CLAUDE.md` と `rules/` を置かないこと。
- CLI の更新で新しいキーが書き足されて起動前検査が止まったら、そのキーを読んで判断すること。
  - 許可集合を広げるのは要件の改訂なので、`/revise` を通す。
- 管理設定(`/etc/claude-code/`)は製品では塞げない。そこに何を置くかは人間の責任として残る。

### Reversibility

- **可逆**。検査は最小ホームに何も書かないので、コミットを revert すれば戻る。
- フィクスチャの取り直しで消費したレート枠は戻らない。数回ぶんで、D-108 と同じ扱い。
