# ADR-029: 呼び出しの入力と出力を減らす(分類の解説、recall 生成の思考、含意判定のまとめ)

- **Status**: proposed
- **Date**: 2026-10-14
- **Decider**: human (finalized at the mandate)
- **Related requirements**: NFR-7、NFR-1、R-3、R-4

## Background / problem
フル処理の試行3(列 876150982ad5…)では、cluster 段だけで5時間枠の 68% を使い、recall 段は 51 問で 31% を使った(190 問なら約 1.15 枠)。呼び出しログ(`out/aip-c01/t071/013.stderr`、`014.stderr`)の内訳は次のとおり。

| 呼び出し | 回数 | 入力トークン | 出力トークン |
|---|---|---|---|
| 分類(Opus 5.5) | 8 | 65 万 | 1.5 万 |
| 要約(Opus 5.5) | 31 | 69 万 | 2.7 万 |
| cluster の含意判定(Sonnet 5.5) | 30 | 59 万 | 0.2 万 |
| recall 生成(Haiku 4.5) | 61 | 43 万 | 22 万 |
| recall の含意判定(Sonnet 5.5) | 109 | 49 万 | 0.8 万 |

原因は3つある。

- 事前の抽出が無い。どの呼び出しにも問題の全文を送っており、解説がデッキの文字数の 76% を占める。分類にも解説を送っている。
- recall 生成は既定で思考する。プローブ(`docs/test/measurements/thinking-probe.md`)では出力 1,658 トークンのうち約 1,340 が思考で、`MAX_THINKING_TOKENS=0` で 315 に下がった。`--effort low` では止まらない。
- 含意判定は主張ごとに1回呼び、そのたびに同じ問題の全文を reference として送り直している(recall は1問あたり約2回)。

CLI の固定オーバーヘッドは1呼び出し約 1,000 トークンで、主因ではない。

## Decision
1. **分類の入力から解説を外す。** `classify_clusters` には問題文・選択肢・正解だけを渡す。論点の分類は問題文と正解で決まる。要約・生成・含意判定の入力の解説は変えない(根拠そのものなので、削ると NFR-1 が弱まる)。
2. **recall 生成の子プロセスだけ思考を止める。** 子の環境の鍵の固定(NFR-8、`claude_process.CHILD_ENV_KEYS`)はメソッドの表から組み、`generate_recall` にだけ `MAX_THINKING_TOKENS` を許す。 メソッドごとの子プロセスの追加の環境変数を `llm_prompts` に `MODELS` と並べて置き、`generate_recall` だけ `MAX_THINKING_TOKENS=0` にする。argv は変えないので argv のダイジェストは動かない。ただし Haiku 4.5 の固定オーバーヘッドは条件が変わる(プローブで入力が 176 トークン減った)ので、その環境で取り直す。Opus の要約と Sonnet の判定は、出力が小さく(1回 860 / 70 トークン)、品質に効くので止めない。
3. **含意判定を1問1回にまとめる。** 判定器のポートを `check_entailments(reference, statements)` の1本にし、主張(`id`、本文、任意の `focus`、任意の `distractors`)の列を受けて、主張の ID ごとの判定値を返す。reference は問題ごとに `reference_for(question)`(正解 N 件と解説)を1回だけ渡す。`focus`(その要素が説明する正解)と `distractors`(識別ポイントが参照する誤答の本文)は reference の節から主張の側へ移す。答えの要素の判定に誤答の本文が混ざらないので、前の振る舞い(答えの reference に誤答の節が無い)を保つ。応答の ID の欠けや余りは `INCOMPLETE_IDS`。集約(`judge`)の規則は変えない。単一の主張の判定(クラスタ要約、グロッサリ、ミューテーション)も同じポートで1件として呼び、`check_entailment` は残さない。
4. **合成デッキのリハーサルを script 段まで広げて取り直す。** まとめた判定と思考なしの生成を、試行4より前に実 CLI で通す。

## Options considered and rejected
- **含意判定の reference を主張に関係する部分だけに絞る**: 削減は最大だが、「reference が正解 N 件すべてと解説を含む」(NFR-1)を崩す。照合の根拠が欠けると誤学習を防ぐ仕組みが弱まるので採らない。
- **全メソッドで思考を止める**: 要約と判定の出力は既に小さく、削減は僅かである。一方で、要約の質と判定の精度を下げうるので採らない。
- **`--effort low`**: 思考が止まらなかった(プローブ)。
- **次サイクルに回す**: 人の判断で採らない(2026-10-14)。

## Consequences
- 見込み(推定、試行3の実測からの外挿):
  - 分類の入力が約7割減る。
  - recall 生成の出力が約8割減る。
  - recall と script の判定の入力が約半分になる。
  - 1列の5時間枠の消費は 2〜3 個から 1.5〜2 個程度に下がる。リハーサルの記録で確かめる。
- プロンプト、スキーマ、メソッドの環境が変わるので、cluster・recall・script 段のキャッシュ鍵が動く。試行4は `--fresh-run` から始める。
- 判定の呼び出しが1問1回になるので、`contradicted` の時点で残りを聞かない早期終了は問題の内側では効かなくなる(問題をまたいでは効く)。
- 途中結果(ADR-028)の判定値は、主張ごとの記録から呼び出しごとの記録になる。旧形式は読まない(後方互換を持たない)。
- `ENTAILMENT_SYSTEM` が変わるので、旧プロンプトの子の記録を含む journal を render が読めなくなる。render は記録する列(本列と使う再現性の列)の標準エラーだけを読む(T-084)。
- 固定オーバーヘッドの定数の鍵は argv と skills のダイジェストで、環境は入らない。環境はコードの表で決まり、較正の記録の環境の鍵が製品の表と一致することを記録の検査で見る(T-083)。
- まとめた判定の精度は、合格ラインを置かずに、合成のミューテーションの検出数を T-068 の記録に残して見る(D-044)。
