## Notes / design decisions

- 2026-09-27 に再承認前のベースラインで見つかった(D-162)。
  - 作業ディレクトリには `web/node_modules/` がある。これは `web/.gitignore` が無視している。
  - 走査はルートの `.gitignore` しか読まないため、第三者パッケージの文字列を認証情報の形として拾い、C-015 と C-018 が赤になる。
  - HEAD を `git archive` で取り出した木では、サンドボックスで 376 件が緑だった。
- ベースラインは、このタスクが直すまで赤として `--freeze` で記録する。着地したら、`web/node_modules/` のある作業ディレクトリで `rein baseline measure` を測り直す。`test` ステップが緑に戻ったことを確かめてから、凍結を外す(AR-176)。
- 変えるのはテストファイルだけなので、negative control は取れない(記録はされるが、合格としては扱われない)。修正前に赤だったことは、レビューで確かめる。
- 敵対的レビュー(2026-09-27)の処置:
  - AR-174(major): A-1 が、ハードコードや、入れ子の規則をルートからの相対で当てる誤った実装でも通った。固定パターン、2段の入れ子、ルート直下の同名ディレクトリの3つを A-1 に足した。
  - AR-175(major): `is_ignored` は1ファイル分の規則しか評価しないので、階層をまたぐ否定の優先順位を表せない。黙って進むと、無視しすぎの向きに誤る。否定を見つけたら失敗させる形(A-3)にした。いまのリポジトリの入れ子の `.gitignore` は `web/.gitignore` だけで、否定を含まない。
  - AR-176(major): 凍結した赤を外す出口が無かった。上に書いた。
  - AR-177(minor): T-047 の票の blockedBy に T-049 が無い。票は変えずに残す。票を変えると、T-047 の不可逆ゲートの承認が再承認で持ち越されなくなるため。依存の真は `plan.yaml` の側にある(`blocked_by: T-045, T-046, T-049`)。
