## Acceptance criteria
> 機械が読む写しは `.rein/plan.yaml` のこのタスクの `acceptance:`。

- **A-1**: check_entailments は reference を1回、主張の列を1回の子プロセスで渡し、判定値を主張の ID で対応づけて返す。ID の欠けか余りは INCOMPLETE_IDS。check_entailment はポートにも実装にも無い。  
  判定: command — `pytest -q tests/adapters/test_llm_claude_cli.py::test_check_entailments_maps_verdicts_by_id`
- **A-2**: recall 段は1問の1回の生成につき判定を1回だけ呼び、reference は正解 N 件と解説で、答えの要素ごとに focus、識別ポイントに誤答の本文を主張の側で付ける。答えの要素には誤答の本文が無い。要素2だけが contradicted なら作り直し、上限を超えたら RegenerationExhausted。  
  判定: command — `pytest -q tests/recall/test_generate.py::test_entailment_is_one_call_per_question`
- **A-3**(D-248 で外した): script 段はトラックの中の1問ぶんを1回で聞き、判定値を途中結果に残す。1件でも contradicted か uncertain なら EntailmentRejected、再開しても止まる。  
  判定: command — `pytest -q tests/script/test_generate.py::test_entailment_is_one_call_per_question`
- **A-4**: NFR-1 の既存の判定のテストが緑。reference の節を見ていた検査は、同じ性質を主張の側で見る形に書き換える。  
  判定: command — `pytest -q tests/safety tests/recall tests/script tests/cluster tests/glossary tests/acceptance`
- **A-5**: render は記録する列の標準エラーだけを読み、旧プロンプトの子の記録を持つ別の列の実行が journal にあっても記録を作る。  
  判定: command — `pytest -q tests/measurements/test_full_run_logs.py::test_render_reads_only_the_recorded_runs_stderr`
