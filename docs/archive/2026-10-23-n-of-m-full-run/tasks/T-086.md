## To do
- ポートの `summarize_cluster(members, retry=None)` と `generate_recall(question, language, retry=None)` に、前回の出力と落ちた検査を渡す型(`Retry(previous, problems)`。`problems` はそれまでの全回の検査の名前とその対象。`repr=False`)を足す。累積するのは、3回目で1回目と同じ語句に戻らないようにするため。
- `cluster/summary._summarize`: 実在性検査に落ちたら問題文に無かった語句を、含意判定に落ちたら判定値を、前回の要約と一緒に次の呼び出しへ渡す。
- `recall/verify.check_question`: `QuestionCheck` に検査ごとの対象を持たせる(ungrounded_key・generic・duplicate_key はキーの語句、answer_mismatch・missing_options は選択肢 ID、empty は要素、verbatim は対象なし)。対象を generate.py で算出し直さない(検査を二重にしない)。
- `recall/generate`: 落ちた検査とその対象、含意判定(consistent でなかった主張と判定値)を、前回の素材と一緒に次の呼び出しへ渡す。前回の素材と対象の選択肢 ID は、`recall_payload` と同じ不透明キー(o1…)に変換して渡し、元のラベルを渡さない(D-206)。途中結果(ADR-028)には、作り直しの前に落ちた素材と理由を残し、`--resume` しても同じ理由で作り直す。
- `ClaudeCliLlm`: stdin に `retry` を足す(argv は変えない)。`SUMMARIZE_SYSTEM`・`RECALL_SYSTEM` に、`retry` があれば前回の出力の問題を直して書き直すことと、各検査の名前の意味を書く。
- 理由の本文(語句・主張・選択肢)をログと例外文に出さない(NFR-2・NFR-3)。`logger.info` の作り直しのログは検査の名前と回数だけ。
- 修正前に失敗するテストを先に書く(同じ入力で呼び直していることが赤になる)。

## Acceptance criteria
> 機械が読む写しは `.rein/plan.yaml` のこのタスクの `acceptance:`。

- **A-1**: 要約が実在性検査に落ちると、次の呼び出しは前回の要約と、それまでの全回の問題文に無かった語句を受け取る。含意判定に落ちると前回の要約と判定値を受け取る。最初の呼び出しは理由を受け取らない。ログに語句と要約の本文が出ない。  
  判定: command — `pytest -q tests/cluster/test_summary.py::test_regeneration_receives_the_previous_summary_and_why_it_failed`
- **A-2**: 想起素材が検査か含意判定に落ちると、次の呼び出しは前回の素材と、それまでの全回の落ちた検査の名前とその対象を受け取る。選択肢は不透明キーで渡る。作り直しの途中で止まって `--resume` しても同じ理由を受け取る。ログに本文が出ない。  
  判定: command — `pytest -q tests/recall/test_generate.py::test_regeneration_receives_the_previous_material_and_why_it_failed`
- **A-3**: 理由は stdin の `retry` に載り(argv は変わらない)、理由の本文は invocation のログと例外文に出ない。  
  判定: command — `pytest -q tests/adapters/test_llm_claude_cli.py::test_retry_goes_to_stdin_and_not_to_logs`
- **A-4**: `SUMMARIZE_SYSTEM` と `RECALL_SYSTEM` が retry の扱いと各検査の名前の意味を書いており、cluster・recall 段のダイジェストが動く(旧形式の途中結果は使われない)。`Retry` は repr に本文を出さない。  
  判定: command — `pytest -q tests/adapters/test_llm_contract.py::test_prompts_explain_retry_and_check_names`
