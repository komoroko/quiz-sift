## Automated-test approach (the basis for the green decision)

- **Test kind**: unit / integration
- **Test file(s)**: `tests/measurements/test_pre_commit_log.py`, `tests/test_gate_environment.py`
- **Test target / cases** — 各ノードについて **何を壊すと赤になるか**:

  - **A-1**: `Path(...).exists()` を assert するだけのテスト(subprocess で gate.sh を叩かない)→ このノードは緑になってしまうので、**テスト本体が subprocess.run(['bash','gate.sh','smoke']) を呼ぶこと自体が基準**
  - **A-2**: CI から types の run 行を1本消す → 赤(実測済み)
  - **A-3**: requirements.txt の pin を1つ書き換えてイメージを焼き直さない → 赤(実測済み)
  - **A-4**: pre-commit が失敗したログを記録する → 赤(終了コード 0 を assert しているため)

> ノード ID は「その名前のテストが存在すること」までしか強制しない — **空の本体(`pass`)でも exit 0 になる**
> ことは実測で確かめてある。上の行は、実装者とレビュアーがその空白を見つけるための唯一の非循環な手掛かりで、
> 最終的な防御はタスク DoD の `review` ステップ(コードレビュアーがテストを読む)。
