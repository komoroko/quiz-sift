# ADR-024: 子の出力本文をログにも別ファイルにも残さない(D-097 を覆す)

- **Status**: proposed
- **Date**: 2026-10-06
- **Decider**: human (finalized at the mandate)
- **Related requirements**: NFR-2

## Background / problem

前サイクルは子の stdout/stderr を、マスクしたうえで呼び出しの記録(INFO ログ)に載せていた。マスクは登録した文字列全体しか伏せない。DEF-1 の修正で想起キーが問題文の逐語の断片になると、教材の断片がそのままログに出る(SEC-003)。
加えて、`adapters/llm_contract.parse_entailment` は未知の判定語を例外文に入れており、それが `cli.py` の warning に出る。

## Options

### Option A: 本文を一切残さない(採用)
- Overview: `InvocationRecord` から `stdout_masked`/`stderr_masked` を削除する。子の出力から作った値を例外文にも載せない。記録に残すのは構造化項目(argv・終了コード・所要時間・4値トークン・失敗種別・レート枠・stdin のダイジェスト・init.tools・isUsingOverage)だけ。
- Security: 教材の断片がログに出る経路を断つ。
- Non-functional: PARSE 失敗の原因を記録から調べられなくなる。フル処理で SCHEMA/PARSE に落ちたとき、同じ実教材での再現は、人が手で CLI に流す以外に無い。それはゲートの外で教材を最小ホームのセッション記録に残す行為なので、行わない。診断は合成の入力での再現で試みる(D-214)。
- Implementation effort: 最小。

### Option B: 本文を `.gitignore` 済みの `out/<deck>/invocations/` に書く
- Pros / cons: 診断は残るが、教材が置かれる場所が増え、人が整理する手間が要る。

## Decision
**Adopted**: Option A

**Reason**: 人の回答(D-172、D-197)。

## Consequences / results
- 本文を含まない製品の集計行(`run_id`、NFR-7 の記録、段ごとの件数)は残る。
- `MaterialTextFilter` は多層防御としてハンドラに残す。
- 子の出力から作った値(判定語、未知のキー、ツール名、subtype/stop_reason)は、どのパーサでも例外文に載せず、種別と件数だけにする。
- 受入テストは、番兵の本文を返す fake で、成功と各失敗経路(SCHEMA・PARSE・TIMEOUT・未知の判定語)を流し、全レベルのログと stderr に番兵が 0 件であることを確かめる。

### What this requires of a person
- PARSE 失敗などの診断が要るときは、合成の入力で再現を試みること。実教材を手で CLI に流さない(D-214)。

### Reversibility
- 可逆(コミットを戻せば元に戻る)。ただし、本文を残さなかった期間の診断情報は後から得られない。
