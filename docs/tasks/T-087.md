## Notes / design decisions
- D-247。試行5(列 cee943ce…)は cluster と recall を通った(190/190、作り直し 17 回、上限を使い切った問題 0)。その後、script 段が `LabelEnumerationFound` で止まった(021.stderr、トラック c003-2・c006-6・c007-3)。
- 選択肢のキーの漏れについて。
  - 選択肢のキーは、D-206 で R-6 のラベルを生成させないために入れた不透明キーである。
  - 試行5の成果物では、190 問中 34 問の本文にキーがあった。ラベル判定が拾ったのは、そのうち括弧の形(8問)だけである。
  - プロンプトは既に「本文では選択肢のラベルやキーで言及しない」と書いている。漏れた 34 問のうち、作り直しのあった問題は3問だけだったので、作り直しの指示から漏れたのでもない。生成の側の検査で落とす。
- c006 について。
  - 問題文が名前として導入した記号(「サプライヤーA」など)を、選択肢の列挙と区別できなかった誤検出である。
  - 緩める範囲を、問題文にその字面がある記号に限る。カタカナ・漢字に続く記号をすべて外すと、「肢A」「オプションA」のようなラベルの言及が素通りする(レビュー AR-H4)。
- プロンプトが変わるので、recall 段のキャッシュ鍵が動き、リハーサルの記録の検査(今のコードとの突き合わせ)が赤になる。そのため、直しと取り直しを1つのタスクにまとめる(D-246 の T-083 と同じ理由)。
- 固定オーバーヘッドの較正は取り直さない。較正の argv は空のシステムプロンプトで作るので、`argv_digest` は動かない。
- 問題の本文に同じ字面のキー(例: モデル名の o1)がある問題では、そのキーの漏れを落とせない。aip-c01 の 190 問には該当が無い(確認済み)。
