## To do
- `script/generate.generate_scripts` は、含意判定をトラックごとに行い、判定値が返った主張ごとに途中結果に書く(ファイル名はトラックの通し番号)。
- 始めに途中結果を読む。判定値のある主張は判定し直さない。`contradicted` か `uncertain` の判定値があれば、1回で走った場合と同じく `EntailmentRejected` で止める(ADR-028、AR-14、AR-25)。
- 1回の実行での集約は従来どおり。`contradicted` が出た時点で残りを問い合わせずに止め、`uncertain` は残りを判定したうえで止める。どちらも成果物を書かない。
- 再開のログは件数だけ(NFR-2)。
- `cli.Pipeline.script` を結線する。
- 呼び出し元の無くなった `safety.entailment.emit_if_consistent` を消し、それを使っていたテスト(`tests/safety/test_entailment.py`、`tests/adapters/test_llm_claude_cli.py`)を `judge` の検査に直す(D-240)。

## Acceptance criteria
> 機械が読む写しは `.rein/plan.yaml` のこのタスクの `acceptance:`。

- **A-1**: script の再実行は、consistent だったトラックを判定しない。判定: command — `pytest -q tests/script/test_generate.py::test_resume_skips_tracks_that_were_judged_consistent`
- **A-2**: `contradicted` か `uncertain` のトラックがあれば、1回の実行でも、そのトラックの後に枠切れで止まった再開でも、トラックの判定の途中で `uncertain` の後に枠切れで止まった再開でも、`EntailmentRejected` で止まり、成果物を書かない。判定: command — `pytest -q tests/script/test_generate.py::test_rejected_track_stops_the_stage_across_resumes`
- **A-3**: 再開のログは件数だけ。判定: command — `pytest -q tests/acceptance/test_analysis.py::test_script_resume_logs_counts_only`

## Automated-test approach (the basis for the green decision)
- **Test kind**: ユニットと受入(スタブの判定器が途中で枠切れの `LlmCallError` を上げる)
- **Test file(s)**: tests/script/test_generate.py(新規)、tests/acceptance/test_analysis.py
- **Test target / cases**: 上の A-1〜A-3。A-2 は2つの筋書きで確かめる。(1) `uncertain` のトラックの後で枠切れ。(2) 1問のトラック(主張2件)で、主張1に `uncertain`、主張2で枠切れの `LlmCallError`。どちらも、再開で判定し直すと consistent を返すスタブを使う(判定し直す実装を赤にする)。
