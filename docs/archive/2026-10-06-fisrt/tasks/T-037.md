## Acceptance criteria

> 機械可読な写しは `.rein/plan.yaml` のこのタスクの `acceptance:` にあり、ループが読むのはそちら。

- **A-1**: RateLimitInfo が status / resets_at / five_hour / seven_day に加えて rate_limit_type / is_using_overage(bool または None)/ overage_status を持つ。ports/metering.py の純関数 rate_limit_stop(kind, is_error, last) は、kind == PROVIDER_ERROR・is_error is True・last is not None・last.status == 'rejected'・last.is_using_overage is False のすべてを満たすときだけ真を返す。5条件のそれぞれを1つだけ崩した5入力(is_using_overage が None の入力を含む)で偽になり、status が allowed / allowed_warning の入力でも偽になる。ports/metering.py に ALLOWED_STATUS の名前が無い(D-128、D-135)。  
  判定: `pytest -q tests/ports/test_metering.py::test_rate_limit_stop_predicate_truth_table`
- **A-2**: 不具合の再現: 子の最後の rate_limit_event が status: allowed のまま、その子が PROVIDER_ERROR(is_error 真)で失敗した実行では、終了行の ended_by_rate_limit.value が偽になり、rate_limit_stopped_invocations が 0 になる。修正前の D-110 判定では真になるので、このテストは修正前のコードで赤になる。失敗した子のすべてが述語を満たすとき(rejected・isUsingOverage 偽・is_error 真)は value が真になり、最後のイベントの status と3つの resetsAt が併記される。2本の子のうち A が rejected で失敗し、B が allowed で失敗した実行は偽になる(述語は子ごとに、その子自身の最後のイベントで評価する)。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_allowed_status_failure_is_not_a_rate_limit_stop`
- **A-3**: end_invocation の引数は (model, turns, usage, cost_usd, is_error, skills_digest) である。record_quota は開いている子に属する。終了行の3つの値は次のとおり。overage_invocations は、isUsingOverage が1回でも真だった子の数。invocations_without_rate_limit_event は、record_quota を1回も受けなかった子の数で、begin_invocation と record_failure(SPAWN)だけで終わった子も含む(D-140)。overage_check は、overage_invocations ≥ 1 なら failed、そうでなく invocations_without_rate_limit_event ≥ 1 なら unknown、どちらでもなければ passed。3値のそれぞれに到達する入力がある。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_overage_counts_and_check`
- **A-4**: Meter が書く開始行のキー集合は record / run_id / execution_id / started_at / cache_mode / stage / env_names / metered_env_names と一致する。終了行のトップレベルのキー集合は、設計 NFR-7 節の一覧(record, run_id, execution_id, started_at, finished_at, elapsed_sec, llm_calls, provider_invocations, model_turns, turns_by_model, max_concurrency, tokens, tokens_by_model, calls_by_model, estimated_cost, disclaimer, prices, overhead, failures_by_kind, failed_invocations, invocations_without_usage, invocations_without_turns, rate_limit_stopped_invocations, ended_by_rate_limit, quota_at_start, quota_at_end, overage_invocations, invocations_without_rate_limit_event, overage_check, stop。sequence は T-038 が足す)と一致する。一覧はテスト側にリテラルで書き写す。quota_at_start / quota_at_end は status / rateLimitType / isUsingOverage / overageStatus / resetsAt / five_hour / seven_day を持つか、届かなければ null になる。stop は exit_code / exit_reason / kind を持つ。各行は1回の write で書き、flush と os.fsync を行う。ファイル末尾が改行でなければ先に改行を1つ書き、途中まで書かれた行と連結させない。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_start_and_end_lines_carry_the_design_fields`
- **A-5**: OverheadConstant が skills_digest を持つ。pipeline/overhead.py の skills_digest(names) は、名前を並べ替えた JSON 配列の sha256 を返し、None のときは固定値 'absent' のダイジェストを返す(期待値はテスト側で計算する。D-141)。観測した skills ダイジェストの集合が {定数の skills_digest} と一致しないモデルの overhead は、status: unknown・reason: skills_mismatch になる。argv も違う場合は reason: argv_mismatch が優先される。定数表は注入し、既定の表に依存しない。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_overhead_is_unknown_on_skills_mismatch`
- **A-6**: 旧 T-002 / T-031 の凍結ノードのうち、この変更で意味が変わらないものが緑のまま残る(D-113)。置き換える2本(test_meter_line_carries_every_nfr7_field → A-4、test_ended_by_rate_limit_follows_d110 → A-2)以外は、消さず、名前も変えない。  
  判定: `pytest -q tests/pipeline/test_meter.py::test_meter_records_run_fields tests/pipeline/test_meter.py::test_token_breakdown_and_price_provenance tests/pipeline/test_meter.py::test_notional_cost_computed_declared_and_unavailable tests/pipeline/test_meter.py::test_price_table_has_two_models_with_sources tests/pipeline/test_meter.py::test_failed_and_usage_less_invocations_are_counted tests/pipeline/test_meter.py::test_overhead_is_unknown_on_argv_mismatch_and_quota_is_recorded tests/pipeline/test_meter.py::test_output_is_notional_and_never_claims_billing tests/ports/test_metering.py::test_run_meter_protocol_and_failure_kinds`
