## To do
- **cluster**(`cluster/summary.py::emit_summarized`): クラスタごとに「要約 → 実在性の検査 → 含意判定」を行う。どちらかに落ちたら、そのクラスタの `summarize_cluster` だけを呼び直す。最初の1回と合わせて最大 `1 + MAX_REGENERATIONS` 回(`MAX_REGENERATIONS` = 2)まで繰り返す。上限を超えたクラスタが出た時点で止め、最後に落ちた検査に応じて `UngroundedSummary` か `EntailmentRejected`(最後の判定値)を上げる。全クラスタが通ったときだけ `emit` を呼ぶ。
- **glossary**(`glossary/verify.py`): 照合先のある用語ごとに判定し、`consistent` でなければその用語の `describe_term` だけを呼び直して判定し直す(上限は同じ)。照合先の無い用語は従来どおり判定しない。全用語を判定したうえで、上限を超えた用語があれば従来どおりの集約(`contradicted` があれば `Contradicted`、無ければ `uncertain` で `EntailmentRejected`)で止める。
- 作り直しのたびに、何を・なぜ・何回目かをログに1行残す。載せるのはクラスタ ID か用語の通し番号と、検査名と回数だけにする(NFR-2)。
- `LlmCallError` は作り直さない(D-101)。

## Acceptance criteria
> 機械が読む写しは `.rein/plan.yaml` のこのタスクの `acceptance:`。

- **A-1**: cluster 段で、要約が実在性の検査に落ちたか含意判定が consistent でなかったクラスタは、そのクラスタだけ要約を作り直す。スタブが MAX_REGENERATIONS(= 2)回落ちてから通る要約を返すと、そのクラスタの summarize_cluster はちょうど 3 回呼ばれ、作り直した要約で成果物が書かれ、他のクラスタの summarize_cluster は 1 回だけである。  
  判定: command — `pytest -q tests/cluster/test_summary.py::test_rejected_summary_is_regenerated_for_that_cluster_only`
- **A-2**: cluster 段で、含意判定に 3 回続けて落ちたクラスタがあれば EntailmentRejected、実在性の検査に 3 回続けて落ちたクラスタがあれば UngroundedSummary で非0終了し(落ち方が混ざれば最後に落ちた検査で決める)、どちらも summarize_cluster はそのクラスタで 3 回だけ呼ばれ、成果物は書かれない。  
  判定: command — `pytest -q tests/cluster/test_summary.py::test_summary_regeneration_exhausted_still_stops`
- **A-3**: glossary 段で、含意判定が consistent でなかった用語は、その用語だけ説明を作り直す。スタブが 2 回落ちてから通る説明を返すと、その用語の describe_term はちょうど 3 回呼ばれ、作り直した説明でグロッサリが書かれ、照合結果は Consistent(照合件数)のままで、他の用語の describe_term は 1 回だけである。  
  判定: command — `pytest -q tests/glossary/test_verify.py::test_rejected_description_is_regenerated_for_that_term_only`
- **A-4**: glossary 段で、3 回続けて consistent でなかった用語があれば、全用語を判定したうえで EntailmentRejected で非0終了し、グロッサリを書かない。その用語の describe_term は 3 回だけ呼ばれる。  
  判定: command — `pytest -q tests/glossary/test_verify.py::test_description_regeneration_exhausted_still_stops`
- **A-5**: 作り直しのたびにログが1行出て、クラスタ ID か用語の通し番号と検査名・回数だけを含み、要約・説明・用語の本文を含まない(NFR-2)。cluster・glossary の2段それぞれで、作り直しを起こしたときにログが出ることと本文が出ないことを確かめる。  
  判定: command — `pytest -q tests/acceptance/test_analysis.py::test_regeneration_logs_name_ids_and_counts_only`

## Automated-test approach (the basis for the green decision)
- **Test kind**: ユニットと受入(スタブの LLM が呼び出しごとに、落ちる生成物を k 回返したあと通る生成物を返す)
- **Test file(s)**: tests/cluster/test_summary.py、tests/glossary/test_verify.py、tests/acceptance/test_analysis.py
- **Test target / cases**: 上の Acceptance criteria の各項目。上限が 2 であることは、「2 回落ちてから通る → 書かれる、呼び出し 3 回」と「3 回落ちる → 止まる、呼び出し 3 回」の両方で固定する(どちらか一方だけでは、上限が 1 でも 5 でも緑になる)。
- **既存テストの扱い**: 次のテストは変わった方針に合わせて直す。
  - 「実在性で止まると含意判定は1度も呼ばれない」(`tests/cluster/test_summary.py` の `llm.checked == []`)。クラスタごとの順序に変わるので、落ちるクラスタより前のクラスタは判定される。
  - 常に矛盾を返すスタブで、生成や判定の呼び出し回数を数えているもの

## Notes / design decisions
- 背景(D-232、ADR-026): フル処理の試行2(2026-10-12、列 47a478dc…)が、cluster 段の要約の contradicted で止まった。実デッキで cluster 段の要約の検査まで達した5本のうち3本が止まっている。recall の含意判定(約400件)と glossary 段は、実デッキでまだ一度も走っていない。D-191 と ADR-022 の「含意判定の不合格は再生成しない」を改める。recall の側の作り直しは T-063 が受け持つ(D-233)。
- 上限は recall の `MAX_REGENERATIONS`(= 2、D-171)と同じ値にする。cluster と glossary は各モジュールに定数を置き、recall のモジュールを import しない。
- script 段は文を生成せず、recall の文を判定し直すだけなので変えない。recall で通った文が script の判定で揺れて落ちるリスクは残る(mandate で示す)。
- glossary の `describe_term` はデッキの文脈を受け取らない。説明が解説と系統的に食い違う用語は、作り直しても通らない見込みがある(敵対的レビュー AR-3)。合成デッキのリハーサルは足さない(人の判断、2026-10-12)。
