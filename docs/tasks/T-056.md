## To do
- SubprocessRunner.run を start_new_session=True、タイムアウト時 killpg(SIGKILL)、communicate(timeout=5)、まだなら pipe を閉じて wait、の順にする。
- alarm の経路でも killpg する。親の SIGHUP/SIGTERM で子のグループを止める。
- 孫を残す fake を tests/support/grandchild_fake.py に置く。

## Acceptance criteria
> 機械が読む写しは `.rein/plan.yaml` のこのタスクの `acceptance:`。

- **A-1**: pipe を継承した孫(寿命は 60 秒で打ち切る)を残して眠る fake の子を timeout_sec=1 で走らせると、11 秒未満に Outcome.TIMEOUT が返る。テストは run を別スレッドで走らせて join(15) の期限を持ち、修正前のコードでは期限切れで赤になる(無限に待たない)。  
  判定: command — `pytest -q tests/acceptance/test_timeout.py::test_c021_timeout_returns_while_grandchild_holds_pipes`
- **A-2**: 孫が setsid で新しいセッションに抜けた変種でも、11 秒未満に TIMEOUT が返る(孫の終了までは求めない)。  
  判定: command — `pytest -q tests/acceptance/test_timeout.py::test_c021_timeout_returns_when_grandchild_left_the_session`
- **A-3**: 子は start_new_session=True で起動され、タイムアウトでプロセスグループに SIGKILL が送られ、猶予は 5 秒(D-186)。親(cli の主スレッドで入れるハンドラ)が SIGHUP/SIGTERM を受けたときも、走っている子のグループに killpg してから終わる(D-221)。既存の SIGALRM の経路も killpg する。  
  判定: command — `pytest -q tests/test_cli_sequence.py::test_parent_signal_kills_the_child_group`
